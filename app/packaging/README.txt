Orchestrate @VERSION@ — Windows x64 便携版

使用方法
1. 完整解压 ZIP 到当前用户可写的文件夹。
2. 双击 Orchestrate.exe。无需安装 Qt、Qt Creator、MinGW 或 Python。
3. 保留 DLL、插件目录和 tools 目录的相对位置，不要只复制 EXE。

运行环境
Windows 10 1809 或更新版本的 64 位系统；建议使用仍受支持的 Windows 版本。
内置定时关机工具使用 Windows PowerShell 与任务计划程序。
SSH 工具需要本机 OpenSSH 客户端及已配置的免交互登录；外部工具需要自己的依赖。
WSL 工具需要已安装并初始化的 WSL 发行版及 Linux 工具依赖，通过 wsl.exe 原生调用，无需 PowerShell 包装。
“注册远程工具”提供 SSH/WSL 两种入口；SSH 默认列表只展示 ~/.ssh/config 直接声明的别名。
注册窗口支持选择或填写用户，成功后保存实际用户名；这里不会创建系统或服务器账号。
内置定时关机仅展示开启、关闭、设置弹窗时间、设置弹窗持续时间四条命令。

数据与升级
首次运行在程序旁创建 data/orchestrate.sqlite3；工具状态在 tools/<工具>/state/。
升级或备份前，从托盘菜单选择“退出 Orchestrate”，再备份整个 data 目录和工具 state 目录。
v1.1.0 起可在“设置 → 版本与更新”检查 GitHub 正式 Release，下载、校验并安装更新。
安装前先结束运行中的工具及关机倒计时。v1.1.2 起安装时自动暂停本目录相关计划任务，结束后恢复原状态。
从 v1.1.0/v1.1.1 升级本版时仍由旧更新器执行：需手动暂停相关任务，升级后手动重新启用一次。
自动更新需要程序上级目录可写；保留个人数据、配置及程序路径，更新过程中在旁边临时保存完整旧版备份。
替换失败或新版未完成启动会恢复旧版。更新结果与备份位置在设置页显示。
v1.1.3 修复更新重启后只有后台进程、主窗口无法唤起的问题；兼容旧更新器的隐藏启动参数。
新版启动确认同时检查主窗口实际可见；更新器以正常窗口方式启动应用，托盘和快捷键可恢复原生窗口。
新版确认启动且任务恢复完成后，自动删除下载 ZIP、解压文件和更新临时目录；同时清理本次旧版完整备份；失败或任务恢复未完成则保留恢复材料。
启动时补清旧更新器留下的成功残留；清理遇到占用时下次启动重试，失败更新及任务恢复材料保留。
v1.0.0 首次升级需手动：新版解压到临时目录，复制旧 data、各工具 state 和个人配置，放回原路径。
v1.2.0 的数据库结构为 schema v3；升级前自动备份到 data/backups/，保留原有内容和工具设置。
旧 SSH 注册继续沿用原配置用户；新注册保存明确用户名，确认新条目可用后可移除旧条目。
数据库迁移前的快照在 data/backups/；手动降级时同时恢复旧程序和数据库备份，不能只替换旧 EXE。
本包不包含个人数据库、工具状态、凭证或开机启动配置。
v1.1.1 起不同程序目录的开机自启开关独立，同目录更新保留设置。
升级保留指向当前程序的旧启动项；首次操作开关时迁移并保留 Windows 禁用状态。
移动前在旧目录关闭自启，移动后在新目录重新开启；其他目录的启动项不会自动清理。
旧版本仍使用共享启动项，验证两份程序隔离前请将两份都升级至 v1.1.1。

窗口和后台
关闭主窗口默认驻留托盘，Alt+X 可唤起；托盘菜单可完全退出。
开机自动启动默认关闭，在“设置 → 运行与托盘”中开启。
Alt+X 和定时关机计划任务仍是系统共享资源，本版隔离范围为开机自启。
