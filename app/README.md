# Orchestrate Qt 客户端

Orchestrate 是基于 C++17、Qt 6 Widgets 和 SQLite 的 Windows 桌面工作台。产品统一使用 Orchestrate 名称。

当前版本为 **v3.6.0 可配置工具与命令**：“接入工具”同窗选择“工具目录”或“JSON 配置文件”及本地 Windows、WSL 或 SSH。目录模式优先读取声明，无声明时发现命令；JSON 模式读取指定文件，统一使用 v1 协议。默认加入全部命令，按需展开挑选或编辑。命令支持启停、删除、排序和运行前参数联动；应用内显示输出与退出码，交互任务可打开外部终端。见 [v3.6.0 版本说明](../docs/releases/v3.6.0.md)和[可配置工具开发说明](../docs/development/configurable-tools.md)。

v3.1.0 为记录预览加入离线公式排版：支持 `\(…\)`、`\[…\]`、`$…$` 和 `$$…$$`，覆盖分数、上下标、求和、矩阵与中文注释。公式异步生成，编辑与保存保留原文，预览中复制公式仍得到 LaTeX 文本。该版本数据库为 schema v7。完整变化见 [v3.1.0 发布说明](../docs/releases/v3.1.0.md)，写法见 [公式示例](../docs/math-preview.md)。

- **时序记录**：日历、日记、日记集合、一次性或重复提醒。
- **项目记录**：多环境项目目录与状态、Git 历史内容页、可按文件夹整理的协作记录，支持文件夹重点星标与置顶，以及标题、摘要和文件夹搜索。
- **自动化工具**：工具分组、Windows/WSL/SSH 目录或 JSON 接入、命令发现与编辑、参数联动、应用内或终端运行及可选状态读取。
- **剪贴板**：监听复制、历史与自定义标签页、一层文件夹、搜索预览、手动文本、批量移动及拖动排序；双击复制并收起，手动粘贴。
- **常驻与设置**：开机自动启动、关闭到托盘、Alt+X 唤起、快捷键状态和重试。

WSL 工具在“接入工具”中将执行环境选为 WSL，选择或填写发行版、填写 Linux 用户和工具目录／JSON 文件路径（支持 `~/`）；用户名留空时读取默认用户，接入后固定实际身份。程序直接调用系统 `wsl.exe`，不需要 PowerShell 包装或 WSL 常驻服务。目录扫描使用只读 POSIX 脚本，无 Python 扫描依赖；有声明时直接读取，无声明时发现入口并读取帮助，也可展开手动添加命令。首次使用此版本会先备份旧数据库到 `data/backups/`，再升级至当前 schema v9；回退旧客户端时须同时恢复升级前的数据库。

工具作者从 [工具接入与适配指南](../docs/automation-tool-contract-v1.md) 的统一最小 JSON 模板开始；[最小样例](../docs/examples/tool-adapter/README.md) 可直接复制。每个工具的使用说明见[README 清单与通用查询示例](../docs/automation-tool-contract-v1.md#13-每个工具-readme-应写什么)。

无声明接入支持通用动态下拉发现，接入只读帮助，实际选项在运行表单或测试时查询；选列映射与联动操作见[动态下拉说明](../docs/development/configurable-tools.md#通用动态下拉发现与设置)。

命令表单支持 `choice.options_state_key` 从工具状态读取动态选项，沿用 `state_key` 预选有效的当前值；失效时要求重选。`type: "readonly"` 将声明的状态字段显示在表单顶部，不传入命令。使用状态的表单打开时异步刷新，支持加载、失败重试和空列表提示；手动刷新保留有效选择和已编辑输入，运行前按本次快照校验。静态 `choice.options` 继续兼容，无需升级数据库结构。工具须自行发布脱敏选项，并在执行时再次核验账号与权限，具体格式见接入指南第 7 节。

SSH 工具在同一“接入工具”窗口将执行环境选为 SSH，选择或填写主机、填写登录用户和远端目录／JSON 文件路径。用户留空会沿用 SSH 配置，读取目录后固定实际用户名；路径支持 `~/`。别名下拉只显示默认 `~/.ssh/config` 直接声明的 Host，不列出 Include 引入的工具/扩展连接；别名列表读取不联网，实际 SSH 连接仍使用完整配置。目录扫描与帮助读取在目标环境异步进行；系统 OpenSSH 需已配置非交互认证。

CANNLab 默认加入 demo、menu、accounts、import、environments、start、reset-pending 共 7 条命令；menu 与 start 使用外部终端，start 包含 8 项可提取参数，account／resource 可由通用规则关联 accounts／environments 查询。重复接入无声明的同目录会追加缺失命令并补齐空白简介；与当前帮助原始推断完全相同的参数可升级为动态下拉，已调整字段、非空自定义说明及其他已有配置保留。重复导入声明仍先预览，再确认整套替换。接入不会运行 CANNLab 业务或修改账号数据。

自动化工具页常驻展示工具名称、SSH/WSL 类型和命令，仅在配置了状态文件时显示当前状态。命令名称下显示已有或从帮助中提取的单行简介，过长时省略号截断，悬停查看全文；空白简介不占额外一行，完整说明也保留在可访问描述中。工具介绍仍通过悬停查看。右键左侧工具，选择“查看工具信息”可查看并复制主机、用户、接入声明、工作目录及状态文件路径。“当前状态”右上角提供“刷新状态”按钮，右键菜单也保留刷新入口。状态更新时间与日期不再常驻展示；已移除周期刷新设置及后台轮询，已配置状态文件的工具在启动、选择工具和应用内命令结束时仍会读取状态。

内置定时关机在界面只保留四条命令：**开启定时关机、关闭定时关机、设置弹窗时间、设置弹窗持续时间**。原有脚本维护入口保留；关闭定时关机会同时取消当前倒计时，并保留时间设置。仅取消本次可用弹窗取消按钮或工具目录的 `cancel-shutdown.bat`。

## 构建与运行

本地统一使用 `app/build-qt` 作为唯一开发构建目录，日常测试入口为其中的 `Orchestrate.exe`；不要为单个功能另外创建长期保留的 build 目录。

以下命令从**仓库根目录**执行。需要 Qt 6.11.2 的 MinGW 64 位套件、对应 MinGW 13.1、CMake 3.21+ 和 Ninja。路径按本机安装位置修改。

```powershell
$qtRoot = 'D:/CodeTools/Qt/Qt/6.11.2/mingw_64'
$cmakeExe = 'D:/CodeTools/Qt/Qt/Tools/CMake_64/bin/cmake.exe'
$ninjaExe = 'D:/CodeTools/Qt/Qt/Tools/Ninja/ninja.exe'
$compilerExe = 'D:/CodeTools/Qt/Qt/Tools/mingw1310_64/bin/g++.exe'
$env:PATH = "$qtRoot/bin;D:/CodeTools/Qt/Qt/Tools/mingw1310_64/bin;$env:PATH"

& $cmakeExe -S app -B app/build-qt -G Ninja `
  "-DCMAKE_PREFIX_PATH=$qtRoot" `
  "-DCMAKE_MAKE_PROGRAM=$ninjaExe" `
  "-DCMAKE_CXX_COMPILER=$compilerExe"
& $cmakeExe --build app/build-qt --parallel 3
.\app\build-qt\Orchestrate.exe
```

测试目录仅在本地保留，不纳入版本控制。存在本地测试目录且启用 `BUILD_TESTING` 时才配置 Qt Test 测试目标；不含测试目录的源码可直接构建应用。客户端本身不依赖 Python。

构建应用目标时同步内置工具脚本及声明，排除源目录中的 `state/`；仅修改工具文件后再次构建也会同步。目标目录已有状态不会被覆盖。构建前应完全退出要被替换的程序；关闭到托盘仍然占用可执行文件。

直接双击程序前运行：

```powershell
.\app\deploy.ps1
```

部署脚本使用已配置的 Qt `windeployqt` 路径，并支持 `-BuildDir`。换 Qt 安装位置时同步调整脚本中的路径。为其他电脑分发时，应在单独的干净输出目录构建并部署，不直接打包自己在用的 `data/`、工具 `state/`、测试数据库和个人配置。

## Windows 便携包

从仓库根目录运行 `./app/package.ps1 -ReleaseTag v3.6.0`。需要已提交且干净的工作树、Qt/MinGW/CMake/Ninja，以及与 Qt 对应的源码目录（用于收集第三方许可说明）；工具安装路径均支持脚本参数覆盖。

脚本先检查输出目录已被 Git 忽略，再从 `git archive HEAD` 解出源码，在 `dist/work-*` 中全新 Release 构建（不包含本地测试）。发布前先在 `app/build-qt` 执行本地回归；发布验证完成后可删除 `dist/work-*` 临时目录，只保留发布产物。仅安装程序、更新器与内置工具，再收集 Qt、MinGW 运行库、SQLite 插件、Windows Schannel TLS 插件及许可说明。最终生成 `dist/Orchestrate-v3.6.0-windows-x64.zip` 和 `.zip.sha256`，以及本机构建记录 `.build.json`。ZIP 内含源码提交信息和逐文件校验清单，用户完整解压即可运行。已有同名 ZIP 时拒绝覆盖；可通过 `-OutputDir` 指定另一个已忽略目录。

应用运行时版本和 Windows 文件属性版本统一由 CMake 的 `project(... VERSION ...)` 生成。打包会校验版本、必要运行库和个人数据排除，不启动内置工具，不修改现用数据库或开机启动配置；真正无 Qt 的干净 Windows 系统验收仍应在发布前完成。

## 数据与升级

程序数据保存在可执行文件旁的 `data/orchestrate.sqlite3`，包括日记、提醒、项目、工具注册及偏好。程序目录需可写。备份时先完全退出程序，再备份整个 `data/`；工具自己的状态、凭证和配置由工具维护。

已有便携数据库始终优先。首次从早期用户数据目录迁入时，先找当前应用名下的数据库，否则识别同一组织目录下唯一的旧库并复制；多个候选库会提示手动选择。源库保留原位。日记简介、协作记录标题与摘要、命令参数等结构升级会在打开数据库时补齐。

“设置 → 版本与更新”默认开启每天一次的自动检查：启动至少三分钟后异步查询 GitHub 最新正式 Release，上次检查不足 24 小时则延后；检查失败也记录时间，不连续重试。手动检查随时可用。自动检查只读取版本信息，15 秒总超时，响应上限 4 MiB；采用单次长间隔计时器，不新增后台进程。下载、解压准备或等待安装期间暂停自动检查。

发现新版本后，“设置”入口显示“有更新”，收起侧栏后保留更新图标及悬停说明；托盘菜单提供“查看更新”。自动发现的同一版本最多通知一次，手动发现后不再重复弹通知。检查时间、自动检查开关、最新版本缓存与已提醒版本使用 `QSaveFile` 原子保存到程序旁的 `data/update-check.json`，重启后沿用；缓存不可写时跳过自动请求，仍允许手动检查。关闭“自动检查更新”恢复纯手动检查，已知的新版本仍可查看。

更新说明使用 Qt 原生只读文本区，完整显示最新 Release 的 Markdown 标题、列表和正文，支持滚动与复制；不再截取前 1200 字符，也不加载说明中的图片或 HTML。“查看该版本发布页”打开对应版本。说明仅在更新页可见时排版，不合并中间版本的发布说明；上次更新的恢复或清理结果单独显示，不被版本检查覆盖。

下载更新时按版本号比较，下载同名 Windows x64 ZIP，使用 GitHub asset digest（缺失时读取 `.zip.sha256`）校验，再解压校验逐文件清单。不会在后台自动下载或安装。Release 必须采用 `v主版本.次版本.修订号`，附件命名为 `Orchestrate-vX.Y.Z-windows-x64.zip`，发布时同时上传 `.zip.sha256`。

安装更新需要程序上级目录可写。更新器使用系统 Windows PowerShell，无需额外安装依赖。下载和校验阶段不改变计划任务；正式安装时自动暂停引用本程序目录的已启用任务（包括定时关机），成功或回滚后恢复，原本停用的任务保持停用。正在执行的工具或关机倒计时仍需先结束。任务暂停失败则中止安装并恢复已暂停的任务；恢复失败或任务定义被外部修改时，设置页显示具体任务，保留 `suspended-tasks.json` 供手动恢复，不覆盖任务的新定义。安装会检查未保存内容并正常退出客户端，保留 `data/`、工具 `state/`、外部工具及包内未管理的个人配置，在原路径替换完整程序。旧包清单中已移除的文件会被清理。链接或目录联接需要手动升级。

旧版完整目录保存在程序旁的 `<目录名>-backup-时间-随机值`。更新器等待旧进程正常退出并取得该目录的互斥锁，再替换文件；目录替换遇到短时访问拒绝、共享或锁冲突时最多尝试五次，间隔 500 毫秒，其他失败立即返回，旧数据仍受原有回滚保护；以正常窗口方式启动新版。新版必须在 30 秒内完成窗口、数据库初始化和事件循环启动，确认 Windows 主窗口实际可见，并返回匹配的版本及进程号，否则恢复旧版程序和旧数据库并重新启动。旧更新器传入隐藏启动参数时，新版仍会显式显示主窗口；托盘及快捷键唤起同样检查并恢复原生窗口。设置页展示更新及清理结果。只有新版启动确认、计划任务全部恢复后，才自动删除本次完整回滚备份及更新临时目录；失败或恢复未完成时不执行清理。回滚成功时旧程序和数据已恢复到安装目录，失败现场仍保留在更新工作目录。清理遇到占用时保留重试信息，不将成功更新改记为失败，下次启动继续清理。

确认新版启动且任务恢复完成后，自动删除本次回滚备份和同级 `.Orchestrate-update-*` 中本次的下载 ZIP、解压文件和临时目录，更新结果留在 `data/update-result.json`。清理遇到文件占用不会把成功更新记成失败；设置页显示原因，下次启动重试。启动时也会检查旧更新器遗留的成功更新目录，只清理路径、安装归属和成功记录均通过核对的目录；失败、不完整、仍在执行、存在未恢复任务或包含链接的目录保留。旧更新器已清理工作目录时，新版也会依据最近一次成功结果、任务恢复状态、安装版本及精确备份路径，补清这一次备份；不按名称批量删除历史备份，数据库迁移快照不在此清理范围。v1.1.0/v1.1.1 首次升级仍由旧更新器执行，需要手动暂停一次计划任务；升级后的程序会补清成功残留，后续更新自动暂停和恢复任务。

v1.0.0 没有更新入口，首次升级需手动：完全退出并备份旧目录，将新版解压到临时目录，复制旧版 `data/`、各工具 `state/`、自行添加的工具与配置，随后放回原程序路径。不要只替换 EXE。保持路径不变可以继续使用现有开机启动项和计划任务。

数据库使用 `PRAGMA user_version` 跟踪结构版本（当前为 9），迁移在事务内执行。旧库升级前使用 SQLite `VACUUM INTO` 在 `data/backups/` 保存一致快照；迁移失败回滚，来自更高结构版本的数据库拒绝打开。schema v4 增加项目状态与协作记录文件夹；从更早版本迁入的项目默认进行中，记录位于项目顶层。schema v5 为协作记录增加独立摘要，已有记录的摘要留空，原标题、正文、创建与更新时间、文件夹归属均保持不变。schema v6 增加文件夹重点标记，已有文件夹默认未标记，保留原有分类和记录内容。手动降级时同时恢复旧程序和对应数据库备份，不能只换回 EXE。 schema v8 增加项目环境、主机／发行版和用户字段，旧目录默认本地；删除大纲字段和偏好，不生成协作记录。降级至 v3.2.2 须同时恢复升级前 schema v7 数据库。

schema v9 增加自定义配置标记、工具环境变量、命令启用状态和顺序。旧命令默认启用，按原顺序迁入；手动修改过的工具不再被内置声明自动覆盖。降级至 v3.5.6 时须同时恢复升级前的 schema v8 数据库备份。

工具命令的新参数存为 JSON 数组以保留空字符串和特殊字符；旧记录仍可读取，重新读取原始声明可恢复旧版已经丢失的空参数。外部工具不得直接操作客户端 SQLite。

## 当前交互

### 剪贴板模块

左侧“剪贴板”位于“自动化工具”与“设置”之间。右上角可开关监听，首次默认关闭；开关随便携数据库保存。开启后即使切换页面或隐藏主窗口也会记录新复制的内容，完全退出后停止。启用或重启时不补录系统剪贴板已有的内容。

自动记录始终进入带星形图标的固定“历史”标签页顶层，悬停星标所在标签可查看“自动收纳复制的内容”。可新建、重命名、删除自定义标签页；每个标签页可建立一层文件夹。文件夹和条目沿用“项目记录”的树形列表，文件夹可展开、收起并记住状态，未分类内容直接列在标签页顶层。删除文件夹把内容移回所在标签页顶层，删除自定义标签页把内容移回“历史”，都保留内容并解除自动清理资格。“历史”不能删除或重命名。

主界面只显示标签页、搜索、内容树和操作按钮；列表只显示标题或内容开头，不显示复制时间、格式说明、条数、空列表教学或监听成功文案。选中单个条目时显示正文／图片预览，未选中时不占用预览空间。监听状态直接由开关表示，底部仅在操作失败时出现具体错误。

删除条目按所在标签页决定是否确认：“历史”标签页中的条目直接删除，不弹确认；自建标签页中的条目点击删除后只出现一次弹窗，选择“确认删除”即执行。弹窗默认“取消”，关闭弹窗或按 Esc 也会取消。该规则包含文件夹内条目、手动保存内容、搜索结果和多选删除；删除无法撤销。删除标签页或文件夹仍只需原有的一次确认，并保留其中内容。

支持纯文本、网页 HTML 富文本、图片和文件路径列表。HTML 保留原格式供粘贴，界面只预览其文本，不加载网页或远程图片；图片保存为 PNG，文件只保存路径而不复制文件本体，也不保存剪切标记。文件原件被移动或删除后需自行重新定位。单条原始内容合计上限 16 MiB，图片最多 3200 万像素，超过上限在模块底部显示未记录原因。应用显式标为不应被剪贴板管理器记录的内容会跳过；这不是所有敏感内容的自动识别。

单击查看预览，双击或回车将条目写回系统剪贴板，校验成功后隐藏主窗口，随后在目标应用中手动 Ctrl+V；不模拟键盘粘贴。取用已有内容不会重新加入自己的历史，连续复制相同的最新自动历史也不会重复添加。新建可填写标题和纯文本；已有纯文本可编辑，富文本、图片和文件路径可改标题，含文本的非纯文本条目可另存为纯文本。编辑页通过 Ctrl+S 保存并继续编辑，标题右侧显示保存状态；返回、切换模块、关闭内容／窗口及退出程序时保护未保存修改。

标签页可以水平拖动；树内文件夹、同一文件夹内条目和标签页顶层条目各自支持蓝色插入线拖动及 Ctrl+↑/↓ 调位。将条目拖到文件夹上即可归类，拖到列表空白处移回当前标签页顶层，拖到另一个标签页的页签上可跨页移动；Ctrl/Shift 多选后可批量拖动，成功后展开目标分类并保持选中。文件夹和标签页本身仍是平级分类，不嵌套。目标分类以蓝色边框高亮，与排序插入线区分；界面不再提供专门的“移动到…”按钮、菜单或标签页左右移动菜单。

顺序在重启后保留；自动历史的新记录插在顶层条目最前面。搜索固定作用于当前标签页，包含该页各文件夹中的内容；不再提供搜索范围选项。搜索内容、标题或文件夹时会展开匹配分类，清空搜索恢复原展开状态。有关键词的搜索暂停排序与拖动归类，清空后恢复。文件夹双击或回车只展开／收起，不复制和隐藏窗口。

“历史设置”可设置 100–10000 条自动历史，默认 500 条。上限仅统计“历史”顶层的自动记录，不是所有标签页的总容量；下一次成功记录时，在同一事务内按当前列表从底部向上清理超额的自动历史；调序改变清理先后，搜索不改变底层顺序。正在编辑的条目临时跳过，保存失败保留草稿与保护，取消后恢复原有清理资格。其他标签页、文件夹和手动新建、编辑保存或移动归类过的内容均保留。列表不读取图片或完整正文，内容仅在选中时加载；长文本预览最多显示前 20 万字，复制仍使用完整内容。

v3.0.0 数据库为 **schema v7**，新增剪贴板表；从 v6 或更早版本打开时，先在 `data/backups/` 生成一致快照再事务迁移。原日记、项目和工具数据保留。回退已发布的 v2.4.1 时，须同时恢复升级前的数据库。CopyQ 的现有历史没有自动导入，本模块可独立运行。

### 其他模块

内容页顶部统一提供“返回”“独立打开”“关闭”。返回（Alt+左箭头）和切换模块保留页面实例、选择与阅读位置，并先询问如何处理未保存修改；保存或放弃修改后继续，取消或保存失败则留在编辑页。“关闭”或 Esc 处理未保存修改并释放内容。独立窗口内的下级内容仍在同一窗口切换，“收回主窗口”保留同一份草稿、字号和撤销记录；如果收回会离开另一份未保存内容，先处理那份修改。日记、提醒、协作记录与剪贴板保存后都继续编辑。草稿只在本次运行内保留，不提供重启恢复。

项目列表、工具组、同组工具、协作记录文件夹及同文件夹内的记录都可拖动调整位置，蓝色插入线表示落点；选中后也可按 Ctrl+↑/↓。顺序随便携数据库保存，重启、重命名或编辑内容后仍保留。尚未手动调整的列表沿用默认排序；调整后新增条目追加到同层末尾。

重点与普通文件夹各自排序，重点文件夹始终置顶；所有工具组都可调整组间顺序，包括改过名的“未分组”。拖动展开的工具组或文件夹时，落点在子项上也会按整组定位，插入线显示在整组边界。搜索协作记录时暂停拖动，清空搜索即可恢复。工具可直接拖入其他工具组（包括“未分组”），协作记录可拖入其他文件夹或拖到空白处回到项目顶层；跨分类移动不再使用专门菜单。保存失败会提示错误并保留原归属、顺序和选择，拖动归类不单独增加数据库结构版本。实现与审查步骤见 [同层拖动排序开发说明](../docs/development/in-group-drag-sort.md)。

日历是首页。绿色方块表示日记，金色三角表示提醒（包括已完成提醒），两种标记分开放置。未来日期有浅色背景，本月外日期灰淡。日记集合按记录日期倒序，同日按创建时间和 ID 倒序；修改旧日记不会把它移到今天。可按简介和日期搜索。

日记和提醒打开即可编辑，Ctrl+S 保存后继续编辑；标题同行显示保存状态，底部不保留保存按钮或状态栏。日记采用固定的“简介”标签，日期同排显示。提醒的时间、重复方式和关联项目直接可改，说明可留空，内容框放在选项下方并占用剩余空间。日记与提醒正文默认 20pt，各自记住之后的缩放。

协作记录由标题、摘要和正文组成：标题是简短总介绍，摘要由用户整理关键要点，正文保存完整提示词或协作原文。双击记录或按 Enter 默认显示可编辑的摘要，通过标题同行右侧的“摘要／正文”切换；空摘要可直接填写，需要复制时直接选择内容并复制。

协作记录切换摘要和正文时保留各自草稿及撤销记录。标题与正文必填，摘要可留空。Ctrl+S 一次保存三个字段，随后留在当前页面继续编辑；保存状态位于标题与切换按钮之间，底部不保留保存按钮或状态栏。返回、切换模块、关闭内容或窗口（含关闭到托盘）时，如有未保存修改，可保存、放弃修改或继续编辑；保存失败保留草稿并阻止离开，具体原因可在状态文字上悬停查看。只改标题或摘要时保留正文原有换行。

日记、提醒和协作记录的内容页或独立窗口中，鼠标放在正文区域，按住 Ctrl 向上／向下滚动滚轮即可放大／缩小文字。即时编辑与源码共用当前内容的字号，切换视图后保持；标题随正文等比例缩放。缩放保留原文、选择、撤销记录及预览阅读位置，不改变其他已打开内容的字号；普通滚轮仍用于滚动正文。

正文缩放按日记、提醒和协作记录分别记住最后使用的字号，即时编辑与源码共用；协作记录的摘要与正文各自记住字号和内容页内的阅读位置，未打开的正文不预先排版阅读视图。关闭内容、放弃修改或重启程序后仍保留字号偏好，偏好保存在便携数据库中，不修改正文内容。

双击项目列表中的项目会打开绑定目录：本地用系统文件管理器，WSL 先解析所选发行版和用户的目录，再打开对应 Linux 目录；SSH 打开主机、用户及路径信息窗口，并提供复制路径。未设置目录不执行操作。目录失效或连接失败时提示在“项目设置”中检查。

项目列表显示项目名称和状态图标：圆点圆环表示进行中，圆环勾选表示已完结；悬停可查看状态文字。右键项目可在“进行中”和“已完结”之间切换，菜单最后一项“项目设置”负责修改名称和目录。默认进行中；完结项目仍可查看和编辑。

“协作记录”（原“工作记录”）可保存协作过程、交给 AI 的任务说明、要求和提示词。点击“新建文件夹”按用途分类；每个项目独立管理文件夹，同一项目的文件夹名称不可重复。文件夹可展开、收起并记住状态，选中文件夹后添加的记录直接归入该文件夹。拖动记录到文件夹可归类，拖到列表空白处可移回项目顶层；右键文件夹可重命名或删除，删除文件夹会保留其中的记录并移回顶层。文件夹是应用内分类，不会创建或改动磁盘目录。搜索标题、摘要或文件夹名称会显示匹配内容并展开所在文件夹；清空搜索恢复原来的展开状态。

右键文件夹选择“标记重点并置顶”后，文件夹显示金色五角星并排在当前项目的普通文件夹前；多个重点文件夹之间可手动排序，未调整时按名称排序。选择“取消重点标记”会恢复普通文件夹图标，并按普通文件夹的顺序显示。标记随便携数据库保存，重命名、切换项目及重启后仍保留；操作时保留搜索条件、当前选择和文件夹展开状态。

项目名称旁的“Git 历史”按钮支持单击、回车或空格，默认进入主窗口内的内容页，可主动独立打开。同一项目复用内容，返回或切换模块保留筛选、选中与阅读位置；尚未绑定目录时先打开项目设置。提交历史默认显示全部已知分支和标签，分支与标签分别筛选，也可选当前 HEAD，每批加载 200 条；查找定位已加载提交，不隐藏图上的中间行。双击提交或在列表按 Enter 打开详情，按需读取完整说明、变更文件与 Diff；单击只定位，详情页复用且保持原提交，返回后恢复历史列表，合并提交可切换对比的父提交。

“分支对比”页签首次打开和手动刷新时查询所选远端，完整读取分支名称及最新提交编号，显示仅本地存在、仅远端存在、一致、不一致。默认只看差异，可搜索或显示全部；不计算领先／落后，不执行 fetch，不保存 Git 仓库缓存。结果只在本次内容页的内存中保留；成功时仅显示读取状态，不显示数量与读取时间；失败时保留上次成功内容，关闭内容后结束读取，无后台轮询。

项目设置可选择本地、WSL、SSH。WSL 自动列出发行版并识别默认用户；SSH 列出配置的主机，默认沿用配置的用户。Linux 路径支持 `~/`；验证后保存实际用户名与规范路径。普通目录或尚未安装 Git 的环境仍可作为项目绑定。Git 须在目标环境安装，远端沿用该环境已有认证。

删除入口位于“项目设置”窗口左下角，显示为低强调的红色“删除项目…”文字按钮，主界面不常驻删除按钮。单击后打开确认窗口，完整输入“我确认删除（项目名称）”（使用中文全角括号，项目名须精确匹配），确定按钮才可用；点击确定后删除项目、关联协作记录和文件夹，并关闭项目设置。取消删除会回到设置并保留尚未保存的输入。空输入、错名、多余空格、取消或关闭窗口均不会删除。项目目录中的实际文件不受影响。

定时关机仅按 PowerShell 的 -File 脚本绝对路径识别本目录的倒计时进程，不影响其他目录的同名脚本。移动程序后，“开启定时关机”会在重新登记前，按原计划任务记录的明确脚本路径接管并结束旧倒计时；其他操作不扫描同名旧实例。

日记、提醒、协作记录的正文与摘要支持一至六级标题、加粗、斜体、删除线、代码、基本列表、引用、表格与 LaTeX 公式。即时编辑时只展开正在修改的段落或单元格，其他内容继续排版；右键菜单“编辑整篇 Markdown 源码”可切换到完整原文，源码视图右键可“返回即时编辑”。表格支持 Tab 移动和右键行列操作。原文负责保存与撤销；不通过富文本导出改写 Markdown。HTML 和外部图片保持字面文本，链接不自动打开；列表与悬停提示保留原有轻量显示。旧日记没有简介或协作记录没有标题时，以正文首个非空行的前 120 字符回退显示；协作记录摘要始终独立填写。

`OrchestrateMath.exe` 是按需启动的公式渲染子进程，完成后立即退出；普通文本不启动它。主界面异步读取结果，过时请求会取消，渲染异常、超时或超过限制时保留原文。字体与依赖源码随包携带，无需联网、TeX 安装或常驻浏览器。分发时须保留该 EXE，不能只替换主程序。

主窗口关闭时默认隐藏到托盘；“退出 Orchestrate”才完全退出。Alt+X 只在程序运行时有效，设置页可禁用或重试注册。完全退出后，提醒停止；客户端命令子进程也不提供退出后继续运行的保证。

设置 → 运行与托盘中的“开机自动启动 Orchestrate”默认关闭。开启后，在当前用户登录 Windows 时自动打开主窗口，无需管理员权限。v1.1.1 起使用程序目录的规范化绝对路径（统一分隔符、清理 `.`/`..`、忽略大小写）的 SHA256，生成 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `Orchestrate-<目录哈希>` 项。不同目录的两份程序可以分别开关自启，同目录更新保持身份；窗口名称不变，也无需区分开发版与正式版。值为带引号的当前程序完整路径。该设置由 Windows 保存，不随便携 SQLite 迁移。

升级后只读取指向当前 EXE 的旧 `Orchestrate` 项，保留原自启状态；另一目录的程序既不会显示为已开启，也不会删除或覆盖它。首次操作开关时迁移到当前目录的独立项，再清理归属当前 EXE 的旧项。迁移保留旧 Windows 禁用标记，并保留新项已有的禁用决定；保留失败时停止修改。启动和更新健康检查不会主动迁移注册表。两份程序都应升级或重新构建至 v1.1.1；旧版本仍会写入共享项。

移动或复制到新目录视为另一份程序，默认不自启；移动前在旧目录关闭自启，避免遗留无效启动项。客户端不能根据相同文件名判断旧目录是副本还是被移动，因此不会自动删除其他目录的启动项。此隔离仅针对开机自启：数据库和工具状态按程序目录保存，全局 Alt+X 和定时关机计划任务仍是系统共享资源。

再次进入设置页会重读系统状态。若任务管理器或 Windows 设置已禁用该启动项，页面会显示提示并提供系统启动应用设置入口，由用户在那里重新启用；客户端不会把已禁用项改成启用。注册读写失败会显示错误，不显示保存成功。
