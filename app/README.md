# Orchestrate Qt 客户端

Orchestrate 是基于 C++17、Qt 6 Widgets 和 SQLite 的 Windows 桌面工作台。产品统一使用 Orchestrate 名称。

v2.3.2 修复收起自动化工具组时，Windows 无障碍接口可能循环读取旧节点、导致程序无响应和内存暴涨的问题。协作记录文件夹的折叠、展开及搜索也同步修复。继续保留文件夹重点标记与置顶，数据库沿用 schema v6。完整变化见 [v2.3.2 发布说明](../docs/releases/v2.3.2.md)。

- **时序记录**：日历、日记、日记集合、一次性或重复提醒。
- **项目记录**：项目目录与状态、独立大纲窗口、可按文件夹整理的协作记录，支持文件夹重点星标与置顶，以及标题、摘要和文件夹搜索。
- **自动化工具**：工具分组、Windows/WSL/SSH 声明注册、参数表单、命令运行及当前状态读取。
- **常驻与设置**：开机自动启动、关闭到托盘、Alt+X 唤起、快捷键状态和重试。

WSL 工具通过“注册远程工具 → WSL 工具”选择发行版和 Linux 用户，填写 Linux 工具目录或声明路径（支持 `~/`）。程序直接调用系统 `wsl.exe`，不需要 PowerShell 包装或 WSL 常驻服务。工具本身仍须提供有效的接入声明和状态 JSON。首次使用此版本会先备份旧数据库到 `data/backups/`，再升级至当前 schema v6；回退旧客户端时须同时恢复升级前的数据库。

工具作者从 [工具接入与适配指南](../docs/automation-tool-contract-v1.md) 开始；[最小样例](../docs/examples/tool-adapter/README.md) 可直接复制。指南列明当前能力和未实现部分。

命令表单支持 `choice.options_state_key` 从工具状态读取动态选项，沿用 `state_key` 预选有效的当前值；失效时要求重选。`type: "readonly"` 将声明的状态字段显示在表单顶部，不传入命令。使用状态的表单打开时异步刷新，支持加载、失败重试和空列表提示；手动刷新保留有效选择和已编辑输入，运行前按本次快照校验。静态 `choice.options` 继续兼容，无需升级数据库结构。工具须自行发布脱敏选项，并在执行时再次核验账号与权限，具体格式见接入指南第 7 节。

SSH 工具通过“注册远程工具 → SSH 服务器工具”在同一小窗选择本机 SSH 别名、选择或填写登录用户、填写工具目录/声明路径。用户留空会沿用 SSH 配置，注册后固定实际用户名；别名下拉只显示默认 `~/.ssh/config` 直接声明的 Host，不列出 Include 引入的工具/扩展连接；只读、不联网，实际 SSH 连接仍使用完整配置。

自动化工具页只常驻展示工具名称、SSH/WSL 类型、当前状态和单行命令；工具与命令介绍通过悬停查看。右键左侧工具，选择“查看工具信息”可查看并复制主机、用户、接入声明、工作目录及状态文件路径。“当前状态”右上角提供“刷新状态”按钮，右键菜单也保留刷新入口。状态更新时间与日期不再常驻展示，周期刷新设置保持可用。

内置定时关机在界面只保留四条命令：**开启定时关机、关闭定时关机、设置弹窗时间、设置弹窗持续时间**。原有脚本维护入口保留；关闭定时关机会同时取消当前倒计时，并保留时间设置。仅取消本次可用弹窗取消按钮或工具目录的 `cancel-shutdown.bat`。

## 构建与运行

本地统一使用 `app/build-qt` 作为唯一开发构建目录，日常测试入口为其中的 `Orchestrate.exe`；不要为单个功能另外创建长期保留的 build 目录。

以下命令从**仓库根目录**执行。需要 Qt 6.11.2 的 MinGW 64 位套件、对应 MinGW 13.1、CMake 3.21+ 和 Ninja。路径按本机安装位置修改。

```powershell
$qtRoot = 'D:/CodeTools/Qt/Qt/6.11.2/mingw_64'
$cmakeExe = 'D:/CodeTools/Qt/Qt/Tools/CMake_64/bin/cmake.exe'
$ninjaExe = 'D:/CodeTools/Qt/Qt/Tools/Ninja/ninja.exe'
$compilerExe = 'D:/CodeTools/Qt/Qt/Tools/mingw1310_64/bin/g++.exe'
$env:PATH = "$qtRoot/bin;D:/CodeTools/Qt/Qt/Tools/mingw1310_64/bin;$env:PATH"

& $cmakeExe -S app -B app/build-qt -G Ninja `
  "-DCMAKE_PREFIX_PATH=$qtRoot" `
  "-DCMAKE_MAKE_PROGRAM=$ninjaExe" `
  "-DCMAKE_CXX_COMPILER=$compilerExe"
& $cmakeExe --build app/build-qt --parallel 3
.\app\build-qt\Orchestrate.exe
```

测试目录仅在本地保留，不纳入版本控制。存在本地测试目录且启用 `BUILD_TESTING` 时才配置 Qt Test 测试目标；不含测试目录的源码可直接构建应用。客户端本身不依赖 Python。

构建应用目标时同步内置工具脚本及声明，排除源目录中的 `state/`；仅修改工具文件后再次构建也会同步。目标目录已有状态不会被覆盖。构建前应完全退出要被替换的程序；关闭到托盘仍然占用可执行文件。

直接双击程序前运行：

```powershell
.\app\deploy.ps1
```

部署脚本使用已配置的 Qt `windeployqt` 路径，并支持 `-BuildDir`。换 Qt 安装位置时同步调整脚本中的路径。为其他电脑分发时，应在单独的干净输出目录构建并部署，不直接打包自己在用的 `data/`、工具 `state/`、测试数据库和个人配置。

## Windows 便携包

从仓库根目录运行 `./app/package.ps1 -ReleaseTag v2.3.2`。需要已提交且干净的工作树、Qt/MinGW/CMake/Ninja，以及与 Qt 对应的源码目录（用于收集第三方许可说明）；工具安装路径均支持脚本参数覆盖。

脚本先检查输出目录已被 Git 忽略，再从 `git archive HEAD` 解出源码，在 `dist/work-*` 中全新 Release 构建（不包含本地测试）。发布前先在 `app/build-qt` 执行本地回归；发布验证完成后可删除 `dist/work-*` 临时目录，只保留发布产物。仅安装程序、更新器与内置工具，再收集 Qt、MinGW 运行库、SQLite 插件、Windows Schannel TLS 插件及许可说明。最终生成 `dist/Orchestrate-v2.3.2-windows-x64.zip` 和 `.zip.sha256`，以及本机构建记录 `.build.json`。ZIP 内含源码提交信息和逐文件校验清单，用户完整解压即可运行。已有同名 ZIP 时拒绝覆盖；可通过 `-OutputDir` 指定另一个已忽略目录。

应用运行时版本和 Windows 文件属性版本统一由 CMake 的 `project(... VERSION ...)` 生成。打包会校验版本、必要运行库和个人数据排除，不启动内置工具，不修改现用数据库或开机启动配置；真正无 Qt 的干净 Windows 系统验收仍应在发布前完成。

## 数据与升级

程序数据保存在可执行文件旁的 `data/orchestrate.sqlite3`，包括日记、提醒、项目、工具注册及偏好。程序目录需可写。备份时先完全退出程序，再备份整个 `data/`；工具自己的状态、凭证和配置由工具维护。

已有便携数据库始终优先。首次从早期用户数据目录迁入时，先找当前应用名下的数据库，否则识别同一组织目录下唯一的旧库并复制；多个候选库会提示手动选择。源库保留原位。日记简介、协作记录标题与摘要、命令参数等结构升级会在打开数据库时补齐。

“设置 → 版本与更新”默认开启每天一次的自动检查：启动至少三分钟后异步查询 GitHub 最新正式 Release，上次检查不足 24 小时则延后；检查失败也记录时间，不连续重试。手动检查随时可用。自动检查只读取版本信息，15 秒总超时，响应上限 4 MiB；采用单次长间隔计时器，不新增后台进程。下载、解压准备或等待安装期间暂停自动检查。

发现新版本后，“设置”入口显示“有更新”，收起侧栏后保留更新图标及悬停说明；托盘菜单提供“查看更新”。自动发现的同一版本最多通知一次，手动发现后不再重复弹通知。检查时间、自动检查开关、最新版本缓存与已提醒版本使用 `QSaveFile` 原子保存到程序旁的 `data/update-check.json`，重启后沿用；缓存不可写时跳过自动请求，仍允许手动检查。关闭“自动检查更新”恢复纯手动检查，已知的新版本仍可查看。

更新说明使用 Qt 原生只读文本区，完整显示最新 Release 的 Markdown 标题、列表和正文，支持滚动与复制；不再截取前 1200 字符，也不加载说明中的图片或 HTML。“查看该版本发布页”打开对应版本。说明仅在更新页可见时排版，不合并中间版本的发布说明；上次更新的恢复或清理结果单独显示，不被版本检查覆盖。

下载更新时按版本号比较，下载同名 Windows x64 ZIP，使用 GitHub asset digest（缺失时读取 `.zip.sha256`）校验，再解压校验逐文件清单。不会在后台自动下载或安装。Release 必须采用 `v主版本.次版本.修订号`，附件命名为 `Orchestrate-vX.Y.Z-windows-x64.zip`，发布时同时上传 `.zip.sha256`。

安装更新需要程序上级目录可写。更新器使用系统 Windows PowerShell，无需额外安装依赖。下载和校验阶段不改变计划任务；正式安装时自动暂停引用本程序目录的已启用任务（包括定时关机），成功或回滚后恢复，原本停用的任务保持停用。正在执行的工具或关机倒计时仍需先结束。任务暂停失败则中止安装并恢复已暂停的任务；恢复失败或任务定义被外部修改时，设置页显示具体任务，保留 `suspended-tasks.json` 供手动恢复，不覆盖任务的新定义。安装会保存未提交的项目大纲，正常退出客户端，保留 `data/`、工具 `state/`、外部工具及包内未管理的个人配置，在原路径替换完整程序。旧包清单中已移除的文件会被清理。链接或目录联接需要手动升级。

旧版完整目录保存在程序旁的 `<目录名>-backup-时间-随机值`。更新器等待旧进程正常退出并取得该目录的互斥锁，再替换文件；以正常窗口方式启动新版。新版必须在 30 秒内完成窗口、数据库初始化和事件循环启动，确认 Windows 主窗口实际可见，并返回匹配的版本及进程号，否则恢复旧版程序和旧数据库并重新启动。旧更新器传入隐藏启动参数时，新版仍会显式显示主窗口；托盘及快捷键唤起同样检查并恢复原生窗口。设置页展示更新及清理结果。只有新版启动确认、计划任务全部恢复后，才自动删除本次完整回滚备份及更新临时目录；失败或恢复未完成时不执行清理。回滚成功时旧程序和数据已恢复到安装目录，失败现场仍保留在更新工作目录。清理遇到占用时保留重试信息，不将成功更新改记为失败，下次启动继续清理。

确认新版启动且任务恢复完成后，自动删除本次回滚备份和同级 `.Orchestrate-update-*` 中本次的下载 ZIP、解压文件和临时目录，更新结果留在 `data/update-result.json`。清理遇到文件占用不会把成功更新记成失败；设置页显示原因，下次启动重试。启动时也会检查旧更新器遗留的成功更新目录，只清理路径、安装归属和成功记录均通过核对的目录；失败、不完整、仍在执行、存在未恢复任务或包含链接的目录保留。旧更新器已清理工作目录时，新版也会依据最近一次成功结果、任务恢复状态、安装版本及精确备份路径，补清这一次备份；不按名称批量删除历史备份，数据库迁移快照不在此清理范围。v1.1.0/v1.1.1 首次升级仍由旧更新器执行，需要手动暂停一次计划任务；升级后的程序会补清成功残留，后续更新自动暂停和恢复任务。

v1.0.0 没有更新入口，首次升级需手动：完全退出并备份旧目录，将新版解压到临时目录，复制旧版 `data/`、各工具 `state/`、自行添加的工具与配置，随后放回原程序路径。不要只替换 EXE。保持路径不变可以继续使用现有开机启动项和计划任务。

数据库使用 `PRAGMA user_version` 跟踪结构版本（当前为 6），迁移在事务内执行。旧库升级前使用 SQLite `VACUUM INTO` 在 `data/backups/` 保存一致快照；迁移失败回滚，来自更高结构版本的数据库拒绝打开。schema v4 增加项目状态与协作记录文件夹；从更早版本迁入的项目默认进行中，记录位于项目顶层。schema v5 为协作记录增加独立摘要，已有记录的摘要留空，原标题、正文、创建与更新时间、文件夹归属均保持不变。schema v6 增加文件夹重点标记，已有文件夹默认未标记，保留原有分类和记录内容。手动降级时同时恢复旧程序和对应数据库备份，不能只换回 EXE。

工具命令的新参数存为 JSON 数组以保留空字符串和特殊字符；旧记录仍可读取，重新读取原始声明可恢复旧版已经丢失的空参数。外部工具不得直接操作客户端 SQLite。

## 当前交互

日历是首页。绿色方块表示日记，金色三角表示提醒（包括已完成提醒），两种标记分开放置。未来日期有浅色背景，本月外日期灰淡。日记集合按记录日期倒序，同日按创建时间和 ID 倒序；修改旧日记不会把它移到今天。可按简介和日期搜索。

已有日记、提醒及大纲默认预览，点击“编辑”修改；新建直接进入编辑。日记、提醒和大纲窗口保留“预览／编辑”切换，日记采用固定的“简介”标签。提醒只需标题和时间，说明可以留空。

协作记录由标题、摘要和正文组成：标题是简短总介绍，摘要由用户整理关键要点，正文保存完整提示词或协作原文。双击记录或点击“打开”默认阅读摘要，通过“摘要／正文”标签切换；没有摘要时显示“暂无摘要”，可选择“填写摘要”或“查看正文”。右上角“复制正文”直接复制完整原文，在摘要页也可使用。

协作记录右上角“编辑”会解锁标题和当前内容，并显示“取消编辑／保存”；切换摘要和正文时保留各自草稿及撤销记录。标题与正文必填，摘要可留空。“保存”或 Ctrl+S 一次保存三个字段，随后留在当前页面阅读；“取消编辑”恢复上次保存内容，新建未保存记录则关闭。关闭窗口或按 Esc 时如有未保存修改，可保存、放弃修改或继续编辑，保存失败会保留草稿。只改标题或摘要时保留正文原有换行。

日记、提醒、协作记录和项目大纲的独立窗口中，鼠标放在正文区域，按住 Ctrl 向上／向下滚动滚轮即可放大／缩小文字。编辑与预览共用当前窗口的字号，切换模式后保持；标题随正文等比例缩放。缩放保留原文、选择、撤销记录及预览阅读位置，不改变其他已打开窗口的字号；普通滚轮仍用于滚动正文。

正文缩放按日记、提醒、协作记录和项目大纲分别记住最后使用的字号，编辑与预览共用；协作记录的摘要与正文各自记住字号和窗口内的阅读位置，未打开的正文不预先排版阅读视图。关闭窗口、取消内容编辑或重启程序后仍保留字号偏好，偏好保存在便携数据库中，不修改正文内容。

双击项目列表中的项目会用系统文件管理器打开它的目录，支持中文、空格和特殊字符路径。未设置目录的项目不执行打开操作；目录已移动、无法访问或路径不是文件夹时，提示到“项目设置”更新目录。

项目列表同时显示项目名称和状态。右键项目可在“进行中”和“已完结”之间切换，默认进行中；完结项目仍可查看和编辑。

“协作记录”（原“工作记录”）可保存协作过程、交给 AI 的任务说明、要求和提示词。点击“新建文件夹”按用途分类；每个项目独立管理文件夹，同一项目的文件夹名称不可重复。文件夹可展开、收起并记住状态，选中文件夹后添加的记录直接归入该文件夹。右键记录选择“移动到文件夹”可移动到其他分类或项目顶层；右键文件夹可重命名或删除，删除文件夹会保留其中的记录并移回顶层。文件夹是应用内分类，不会创建或改动磁盘目录。搜索标题、摘要或文件夹名称会显示匹配内容并展开所在文件夹；清空搜索恢复原来的展开状态。

右键文件夹选择“标记重点并置顶”后，文件夹显示金色五角星并排在当前项目的普通文件夹前；多个重点文件夹之间仍按名称排序。选择“取消重点标记”会恢复普通文件夹图标和名称排序。标记随便携数据库保存，重命名、切换项目及重启后仍保留；操作时保留搜索条件、当前选择和文件夹展开状态。

项目名称旁的“项目大纲”入口支持双击、聚焦后回车或空格，打开可调整大小的独立窗口。大纲自动保存，窗口随所选项目切换；保存失败会显示错误并阻止切换项目，关闭退出或托盘退出时会重新保存，失败则取消退出、保留编辑内容。数据库初始化失败时只显示错误说明，不开放编辑入口。协作记录列表留在项目页，双击条目打开记录。项目设置负责修改名称和目录。

删除入口位于“项目设置”窗口左下角，显示为低强调的红色“删除项目…”文字按钮，主界面不常驻删除按钮。单击后打开确认窗口，完整输入“我确认删除（项目名称）”（使用中文全角括号，项目名须精确匹配），确定按钮才可用；点击确定后删除项目、大纲、关联协作记录和文件夹，并关闭项目设置。取消删除会回到设置并保留尚未保存的输入。空输入、错名、多余空格、取消或关闭窗口均不会删除。项目目录中的实际文件不受影响。

定时关机仅按 PowerShell 的 -File 脚本绝对路径识别本目录的倒计时进程，不影响其他目录的同名脚本。移动程序后，“开启定时关机”会在重新登记前，按原计划任务记录的明确脚本路径接管并结束旧倒计时；其他操作不扫描同名旧实例。

正文及协作记录摘要支持行首 `# `、`## `、`### ` 三级标题。编辑与保存保留纯文本；链接、HTML、图片和其他 Markdown 语法保持字面文本，不加载外部内容。旧日记没有简介或协作记录没有标题时，以正文首个非空行的前 120 字符回退显示；协作记录摘要始终独立填写。

主窗口关闭时默认隐藏到托盘；“退出 Orchestrate”才完全退出。Alt+X 只在程序运行时有效，设置页可禁用或重试注册。完全退出后，提醒和周期状态读取停止；客户端命令子进程也不提供退出后继续运行的保证。

设置 → 运行与托盘中的“开机自动启动 Orchestrate”默认关闭。开启后，在当前用户登录 Windows 时自动打开主窗口，无需管理员权限。v1.1.1 起使用程序目录的规范化绝对路径（统一分隔符、清理 `.`/`..`、忽略大小写）的 SHA256，生成 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `Orchestrate-<目录哈希>` 项。不同目录的两份程序可以分别开关自启，同目录更新保持身份；窗口名称不变，也无需区分开发版与正式版。值为带引号的当前程序完整路径。该设置由 Windows 保存，不随便携 SQLite 迁移。

升级后只读取指向当前 EXE 的旧 `Orchestrate` 项，保留原自启状态；另一目录的程序既不会显示为已开启，也不会删除或覆盖它。首次操作开关时迁移到当前目录的独立项，再清理归属当前 EXE 的旧项。迁移保留旧 Windows 禁用标记，并保留新项已有的禁用决定；保留失败时停止修改。启动和更新健康检查不会主动迁移注册表。两份程序都应升级或重新构建至 v1.1.1；旧版本仍会写入共享项。

移动或复制到新目录视为另一份程序，默认不自启；移动前在旧目录关闭自启，避免遗留无效启动项。客户端不能根据相同文件名判断旧目录是副本还是被移动，因此不会自动删除其他目录的启动项。此隔离仅针对开机自启：数据库和工具状态按程序目录保存，全局 Alt+X 和定时关机计划任务仍是系统共享资源。

再次进入设置页会重读系统状态。若任务管理器或 Windows 设置已禁用该启动项，页面会显示提示并提供系统启动应用设置入口，由用户在那里重新启用；客户端不会把已禁用项改成启用。注册读写失败会显示错误，不显示保存成功。
