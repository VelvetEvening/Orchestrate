# Orchestrate v2.4.1

修复长日志、超长单行正文和缓慢文件访问造成的界面卡顿，并保持长期后台常驻的轻量运行方式。

## 响应性修复

- 运行日志只追加新增内容并移除超出上限的旧内容，不再反复重建整段文本。仍只保留最近 256 Ki 字符；窗口隐藏或切换到其他页面时暂停日志排版，重新显示时更新。
- 日记、提醒、协作记录和大纲遇到超过 8192 字符的单行时，使用横向滚动避开昂贵的自动折行。原文、中文与表情、复制和撤销重做均保留。编辑会话内沿用该方式以保护撤销重做，新加载的普通正文继续自然换行。
- 本地工具状态刷新、参数窗口读取、导入和重读本地声明，以及打开项目目录改用异步文件访问。网络盘或 Windows 下的 WSL 共享路径变慢时，可以继续操作主窗口；失败或超时会显示结果。
- 本地接入声明增加 1 MiB 读取上限，与状态和远程读取的现有上限一致。
- 修复后台状态读取过程中切换工具时，详情可能一直显示“读取中”的时序问题。

## 后台资源

文件访问只在请求发生时启动无窗口读取进程，不初始化主窗口、数据库或自动化工具。最多并发 2 个请求、等待 32 个请求，30 秒总超时包含排队时间；窗口关闭后取消相应读取，完成后回收进程。没有新增常驻服务、轮询定时器或常驻工作线程，原有刷新频率不变。

## 数据与升级

数据库继续使用 schema v6，从 v2.4.0 升级无需结构迁移。保留拖动排序、重点文件夹和树控件无障碍缓存修复。

可在“设置 → 版本与更新”检查并安装，或下载 `Orchestrate-v2.4.1-windows-x64.zip` 完整解压运行；附件同时提供 `.zip.sha256` 校验文件。安装前结束运行中的工具命令和关机倒计时。
