# Orchestrate v2.3.0

协作记录新增独立摘要，长提示词可以先看要点、再读原文；更新检查加入低频后台提醒，更新说明完整显示。

## 协作记录：标题、摘要与正文

- 原来的“简介”改称“标题”，用于简短介绍整份记录；新增由用户独立填写的摘要，正文保存完整提示词或协作原文。
- 双击记录或点击“打开”默认阅读摘要，通过“摘要／正文”切换。摘要可留空，空摘要提供“填写摘要”和“查看正文”入口。
- 右上角“复制正文”在摘要页也能复制完整原文；“编辑”统一解锁标题、摘要和正文，并显示“取消编辑／保存”。
- 切换摘要和正文保留各自草稿、撤销记录和阅读位置。保存或 Ctrl+S 一次写入三个字段，窗口继续停留在阅读状态。
- 关闭窗口或按 Esc 时，有未保存修改可选择保存、放弃修改或继续编辑；保存失败保留草稿。只改标题或摘要时，保留正文原有换行。
- 搜索支持标题、摘要和文件夹名称。摘要与正文分别记住文字缩放，完整正文的阅读视图在打开时才排版。

## 更新提醒与完整说明

- 默认在启动至少三分钟后异步检查 GitHub 正式版本，每 24 小时最多自动检查一次，跨重启沿用检查时间和已知版本。
- 发现更新后，设置入口显示“有更新”，托盘提供“查看更新”；同一版本最多自动通知一次。系统通知的显示遵循 Windows 通知设置。
- 自动检查采用长间隔单次计时器，不增加常驻进程；检查失败静默处理且不连续重试。可以关闭自动检查，手动检查随时可用。
- 仅自动读取版本信息，下载和安装仍由用户发起；手动检查遇到 GitHub 限流时会显示明确提示。
- 更新说明改为完整、可滚动和复制的阅读区域，修复原先只显示前 1200 字符的问题；上次更新的恢复或清理结果单独展示。

## 数据与升级

本版将数据库从 schema v4 升级至 v5。迁移前自动在程序旁的 `data/backups/` 保存完整数据库快照；迁移在事务内执行，失败会回滚。

已有协作记录的摘要留空，原标题、正文、创建时间、更新时间和文件夹归属均保留。项目状态、大纲、工具注册与其他偏好继续保留。手动降级时需同时恢复旧程序及升级前的数据库备份。

v2.2.0 及更早版本需要在“设置 → 版本与更新”手动检查并安装本次更新，升级后才具备自动提醒。也可下载 `Orchestrate-v2.3.0-windows-x64.zip` 完整解压运行，附件同时提供 `.zip.sha256` 校验文件。安装前请结束运行中的工具命令和关机倒计时。
