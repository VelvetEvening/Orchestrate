# Use a latest-state JSON contract for registered automation tools

> 实现状态（2026-09-29 后续修复）：始终读取 state_path 文件，stdout 仅进入运行日志。读取器校验 schema、tool_id、基础字段、日期时间和 items；支持可选 expires_at 的显式有效期，不从任意 heartbeat 扩展推断健康。状态上限 1 MiB、明细上限 500 项，后台 SSH 读取总超时 30 秒。具体适配要求见 [接入指南](../automation-tool-contract-v1.md)。

Orchestrate 要求能够注册为“自动化工具”的脚本提供结构化结果或状态，而不是让应用从任意文本日志中猜测业务结论。协议采用统一基础字段加工具自定义详情：Orchestrate 统一读取状态、时间、心跳、摘要、产物和日志引用，工具可以在扩展字段中表达自己的业务结果，例如签到子项或生成文件列表。

第一版以当前状态为中心：一个自动化工具默认维护一个 JSON 状态文件，每次运行或状态变化覆盖更新它，不要求 Orchestrate 保存历史运行 JSON。JSON 必须包含有效的当前日期/周期、最近更新时间、工具或命令标识和当前结果，避免每日任务把前一天的成功误显示为今天的成功。运行历史不是核心能力，后续只有在确实需要审计或排错时再增加可选历史。

短任务与长时间或周期性任务都通过状态文件接入；短任务可以同时把摘要输出到 stdout 供用户查看，但不能以此替代文件。声明在注册时校验，状态基础字段在每次读取时校验，业务结论仍需工具自身保证。有效期由生产者通过 expires_at 声明，客户端不对所有工具套用固定时长。

第一版按一个工具注册实例和一个执行目标维护一份当前 JSON。一个工具同时只允许一个活动运行；现有工具也符合这一约束。多个工具命令和周期任务可以共用当前 JSON，但每次更新必须标明最近操作和执行目标。若未来需要并行运行或多实例监测，再扩展协议，而不是在第一版引入历史运行集合。

## Consequences

- 文件生成工具只需报告本次生成结果和当前产物目录，不必保留上一次生成记录。
- 签到工具只需报告当前日期的各站点结果；例如“今天部分成功”不需要把昨天的失败继续带入当前状态。
- 多个工具命令共用一个工具状态时，状态中必须携带最近一次命令标识；并发运行、多个执行目标和状态文件归属仍需后续明确。
- 状态文件必须避免半写入被 Orchestrate 读到，具体写入方式属于实现约束。
