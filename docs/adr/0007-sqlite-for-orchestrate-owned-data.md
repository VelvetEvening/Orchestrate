# Store Orchestrate-owned data in local SQLite

Orchestrate 的项目记录、项目大纲、工作记录、自动化工具组、工具注册关系、命令配置、服务器连接配置，以及时序记录中的提醒和日记，属于 Orchestrate 自己的数据，统一保存在本机 SQLite 中。为了支持便携部署和直接复制给他人使用，数据库放在程序目录下的 `data/orchestrate.sqlite3`，而不是系统用户目录。项目目录只作为关联位置，路径失效不删除项目记录；自动化工具产生的当前状态 JSON 仍由工具自己维护，Orchestrate 直接读取，不把它复制成另一个可竞争的事实来源。

这一边界让 Orchestrate 数据库负责回答“Orchestrate 认识哪些对象以及它们如何关联”，让工具状态文件负责回答“工具当前是什么状态”。第一版不把自动化工具历史运行记录作为必需数据，也不因追求可移植性而把项目正文写入每个项目目录。

## Consequences

- SQLite 是 Orchestrate 数据的单一写入来源；工具状态 JSON 是外部工具当前状态的读取来源。
- 默认数据目录是程序目录下的 `data/`，便携包可以整体复制；如果程序目录不可写，Orchestrate 应明确报错，而不是偷偷切换到 C 盘的用户数据目录。
- 从旧版本升级时，首次启动会尝试把原用户数据目录中的数据库复制到便携目录。优先使用当前应用名对应的旧库，否则识别同一组织目录下唯一的旧库，不依赖此前应用名称；多个候选库需要用户手动选择。已有便携数据库始终优先，旧库保留原位。
- 项目目录可以不可访问、被移动或被删除，项目记录仍然保留并显示路径状态。
- 未来如需备份、导出或跨机器迁移，需要针对 SQLite 和工具目录分别设计，而不是假设复制一个目录即可完成迁移。
- 如果未来增加离线缓存，缓存必须明确标记为“最后已知状态”，不能冒充工具的实时状态。
