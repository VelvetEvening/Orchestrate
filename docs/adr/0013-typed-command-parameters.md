# Let tool commands declare typed parameters

注册后的工具命令原本只能按声明里的固定参数运行，像定时关机这样需要改弹窗时间、改倒计时的工具，只能为每个取值各声明一条命令，或者依赖工具自带的设置窗口。Orchestrate 改为允许工具命令在接入声明中定义带类型的命令参数（文本、整数、时间、选项、开关）：运行前由 Orchestrate 生成表单并校验，再把值填进命令参数列表里的 `{key}` 占位符；参数默认值可以通过 `state_key` 取自工具当前状态 JSON，表单打开时显示的就是工具正在使用的设置。

没有采用“运行前让用户直接编辑整条命令行”：那样会绕过工具接入声明这条接入边界（ADR 0006），用户也容易拼出工具不支持的参数。也没有把调整交给工具各自的设置窗口：各工具的窗口各不相同，Orchestrate 无法预填、校验，也无法在运行结束后按统一方式读回状态。可以调整什么、取值范围是什么，仍由工具在声明中说明，Orchestrate 不猜。

## Consequences

- ADR 0002 中“第一版不把修改定时任务时间等维护性操作纳入工具命令”的限制随之取消：这类调整可以作为带命令参数的工具命令提供。
- 参数值作为独立的命令行参数传给程序：本地工具不经过 shell，服务器工具逐个做 shell 转义。参数类型只约束输入形式，业务上是否合法仍由工具自己校验，例如定时关机拒绝平移 0 分钟。
- 某个命令参数恰好等于一个占位符、而填写结果为空时，这个参数整体不传；开关型参数借此表达“传或不传某个开关”。
- `state_key` 让表单默认值依赖状态 JSON 的字段。工具改名或删除这些字段时，表单退回声明里的 `default`，不会报错。
- 高风险命令如果有参数，参数表单本身就是确认步骤，不再额外弹确认框。
- 命令会随工具演进。重新读取声明或再次注册同一份声明时，Orchestrate 整体替换已登记的命令，保留分组和刷新设置，不需要先移除注册。
