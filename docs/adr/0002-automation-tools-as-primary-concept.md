# Make automation tools the primary automation concept

Orchestrate 不把“自动化任务监测”单独作为一个只能查看状态的模块，而是以“自动化工具”作为核心概念：用户可以登记一个工具、为它登记多个可执行命令、直接发起一次使用并查看本次使用状态，同时也可以使用同一工具监测长时间运行或按周期运行的自动化任务。这样，监测能力与实际执行入口属于同一工作对象，用户不必为“只能监控”和“需要手动触发”的自动化场景维护两套模型。

## Consequences

- 产品语言中，“自动化工具”是主对象，“自动化任务监测”是它的一项能力。
- 后续需要区分工具定义、工具命令和一次具体的工具使用记录，避免把注册配置与某次运行混为一谈。
- 一个工具可以包含多个面向日常工作的命令；例如每日签到作为一个工具，下面可以有“立即签到”和“登录签到站”等命令。
- 工具管理页优先呈现面向实际工作流程的命令。修改定时任务时间这类维护性操作原先不纳入第一版的工具命令，现已放开：工具可以把它们声明为带命令参数的工具命令（见 ADR 0013）。
- 接入方式仍以本地、WSL 或服务器上的命令/脚本为基础，并通过结构化结果、执行状态、输出、日志和心跳判断运行情况；具体接入边界另行确定。
