# Make automation status refresh configurable per tool

Orchestrate 继续在后台监测启用中的自动化工具，但不为所有工具强制使用同一个刷新频率。刷新设置属于 Orchestrate 自己的本地配置，不写入工具接入声明；每个工具默认关闭周期刷新，用户可以在工具详情中启用按间隔或每天固定时间的状态读取。

普通刷新只重新读取工具已有的当前状态 JSON，不重新执行有业务副作用的命令。用户在 Orchestrate 中运行工具命令后，命令结束或产生新结果时，Orchestrate 自动重新读取该工具的当前状态 JSON。工具详情页提供只刷新当前工具的按钮。对于 WSL 或 SSH 工具，普通刷新通过对应执行目标读取状态 JSON；第一版不把只读查询命令作为普通刷新的必要组成。

对于由外部计划任务或服务器调度器运行的工具，Orchestrate 的周期性自动刷新是按配置重新读取状态文件，而不是重跑签到、提交或其他业务操作。没有新状态变化时，Orchestrate 不刷新复杂界面，也不做无意义的高频轮询。

## Consequences

- 工具接入声明只描述工具提供的状态来源，不负责设置 Orchestrate 的刷新周期；Orchestrate 本地数据库保存每个工具的刷新开关和策略。
- 长期运行工具、周期任务和由 Orchestrate 直接发起的短任务可以采用不同刷新方式。
- 手动刷新必须是幂等的状态获取动作，不能因为用户点击刷新就重复执行有副作用的业务命令。
- 未来如果某些服务器工具无法通过文件读取状态，再另行设计只读状态查询接口。
