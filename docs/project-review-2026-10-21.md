# Orchestrate v2.1.2 崩溃排查与资源测量

## 故障证据

Windows Application Error 在 2026-10-21 21:36:55（UTC+8）记录了 v2.1.1 的 APPCRASH，异常为 `0xc0000005`，故障模块为 Qt 6.11.2 的 `Qt6Core.dll`，偏移 `0x11616a`。该地址对应 `QJsonObject` 的拷贝构造，转储显示一次向空地址写入。

转储中的相关栈地址依次对应 `CommandForm::applyState`、工具状态读取的完成回调、`ProcessCapture`、`QProcess` 析构时的 `waitForFinished`，以及 `QWidget` 删除子对象的路径。窗口的 C++ 成员已经开始销毁，子进程在析构中发出 `finished`，回调仍然通过了尚未清空的窗口 `QPointer`，进而访问已销毁的输入列表。

问题出在客户端的对象生命周期，故障记录没有显示内存容量不足。QtCore 是最终发生非法访问的位置，不能据此把问题归因于 Qt 库本身。

## 修复

共享 `ProcessCapture` 通道为每次读取创建普通 `QObject` 请求对象，把进程和信号接收者都归属于该请求。窗口删除请求时，`QObject` 先断开信号连接，再删除子进程，因而不会在窗口析构期间回调窗口成员。正常完成、启动失败、超时、输出超限时也释放请求，避免在多次刷新后累积。

这项修复覆盖使用远程状态的命令参数窗口，以及共用该通道的 SSH/WSL 注册窗口。保持 30 秒默认超时、每通道 1 MiB 输出上限、现有命令参数与状态协议，不增加后台服务或提高轮询频率。数据库继续使用 schema v3。

## 空闲资源测量

环境为 Windows 11 x64、Qt 6.11.2、MinGW GCC 13.1 Release。将 v2.1.1 便携文件复制到隔离目录，创建合成数据库，禁用测试副本的全局快捷键；使用原生 Windows 窗口和系统托盘，不运行外部工具命令。原安装目录仅做只读检查。

| 项目 | 结果 |
| --- | --- |
| 现用便携目录大小 | 约 40.8 MiB，EXE 约 1.7 MiB，其余主要为 Qt 与运行库 |
| 主窗口空闲 6 秒 | 工作集约 64.0 MiB，私有内存约 27.4 MiB |
| 关闭到托盘后空闲 35 秒 | 工作集约 64.0–64.1 MiB，私有内存约 27.4–27.6 MiB |
| 上述两段 CPU 采样 | 系统进程时间计数未观察到增加，不代表长期绝对为零 |
| 现用 SQLite 只读检查 | `PRAGMA quick_check` 返回 `ok`，测量前后文件哈希一致 |

工作集包含共享库驻留页，私有内存不包含这些共享页，两项不能相加。结果支持客户端空闲常驻开销较低的判断；这是短时基线，不覆盖真实 SSH/WSL 连接、外部工具进程、大量状态数据或长时间内存增长。

## 回归范围

本地协议测试新增普通对象、QWidget、QDialog 销毁时的读取取消，以及真实命令参数窗口在远程读取未完成时关闭的场景。先在旧实现运行取消测试：普通对象通过，QWidget 与 QDialog 均失败，销毁期间多触发一次回调。修复后全部通过；同时验证正常完成、失败、超时和超限后进程及请求均被释放。

测试使用无副作用辅助进程与合成数据，不连接真实服务器或执行工具业务。测试源码及转储按仓库约定保留在忽略的本地目录，个人数据库和崩溃转储不进入发布包或 Git。

v2.1.2 开发构建的 19 个 CTest 套件全部通过，其中协议测试为 36 passed / 0 failed / 1 skipped；默认跳过需要显式选择真实 WSL 环境的测试。本轮还通过了原生窗口可见性、数据库、文本界面及模拟更新回滚与计划任务分支的既有回归。

新增的对象/窗口销毁取消与参数窗口关闭测试另以 `QT_QPA_PLATFORM=windows` 验证，原生 Windows 平台同样通过。
