# Orchestrate 项目审查（2026-09-29）

本轮审查覆盖当前工作树，不局限于上一轮改名差异。重点是工具接入文档能否指导后续工具可靠适配，同时检查客户端主流程、SQLite、文本组件、定时关机脚本、构建部署和测试。工作区中已有大量未提交改动，本轮保留它们，未做提交或清理。

## 结论

本地和 POSIX SSH 工具可以按 [接入指南](automation-tool-contract-v1.md) 完成声明、命令及状态文件接入。指南已经明确路径、参数、身份更新、生产者职责和客户端边界，并提供 [可运行样例](examples/tool-adapter/README.md)。本轮修复了会导致错误目标执行、参数丢失及工具发布不一致的问题。

后续修复已完成下列六项待办，并加入项目删除的双击及名称确认防护。客户端现在校验状态归属、支持显式有效期、限制后台 SSH 读取时长和运行输出量；仍不是完整的任务调度器，业务调度、跨进程锁和持续服务生命周期继续由工具负责。

## 后续修复结项（2026-09-29，六项已完成）

### 已修复 P1：工具资料与命令替换的原子性

位置：`AutomationPage::registerToolManifest`、`applyManifestUpdate`、`syncBuiltinTools` 和 `AppDatabase::replaceToolCommands`。

新增 AppDatabase::saveAutomationTool，在同一事务内保存工具资料并替换全部命令，提交成功才返回新 ID。首次注册、重复导入、重读声明和内置工具同步均使用此入口；更新保留分组与刷新偏好，内置身份不可降级。隔离 SQLite 触发器在第二条命令插入时制造失败，确认资料、命令和内置身份一起回滚，首次注册失败不留下半成品；同时验证空命令列表可正常提交。

### 已修复 P2：状态结构、归属和显式有效期

位置：`readStateFile`、`readToolState`、`startAsyncSshStateRead`、`renderState`。

本地和 SSH 使用同一校验器，检查 schema、与声明一致的 tool_id、result、summary、带时区 updated_at、有效 current_date 和可选 items。状态上限 1 MiB、明细上限 500 项。错误状态清除旧缓存并显示读取失败；本地缺少文件仍显示暂无状态。新增可选 expires_at，由工具明确有效期，缓存到期后显示“已过期”；未声明时不推断统一业务超时。测试覆盖错 ID、缺失/错误字段、无时区时间、无效日期、大小限制、到期边界、本地与模拟 SSH 读取、关闭自动刷新后的缓存过期。

### 已修复 P2：后台 SSH 读取总超时与恢复

位置：`startAsyncSshStateRead`。

后台状态读取从启动起设置 30 秒总超时，超时终止本地读取进程、清理占用、显示可重试错误；结束、启动失败和超时统一只完成一次。进程退出后回收，错误/输出同样有大小上限；删除或改变注册后不接收旧请求结果。使用隔离辅助进程模拟阻塞、恢复后成功、错误归属和启动失败，未连接真实 SSH 主机。

### 已修复 P2：运行输出限额与连续 UTF-8 解码

位置：`runCommand` 的 readyRead 回调、`decodeOutput`、`renderRunRecord`。

每次运行保留一个 UTF-8 解码器，结束时排空解码状态；每次读取至多 64 KiB，最近输出保留末尾 256 Ki 个 UTF-16 代码单元，明确标注截断并避免截断代理对。连续输出最多每 100 毫秒重绘一次，运行结束立即更新。完整日志由工具自己写文件。真实辅助进程逐字节输出中文和 emoji，再输出超过 1 MiB 的文本，验证中文完整、保留尾部、缓存受限。

### 已修复 P2：定时关机进程的精确路径识别

位置：[shutdown-lib.ps1](../app/tools/scheduled-shutdown/shutdown-lib.ps1) 的 `Get-ShutdownReminderProcess`、`Stop-ShutdownCountdownWindow`。

只识别明确 -File 参数中的脚本绝对路径，按 Windows 大小写规则比较；拒绝命令字符串、其他目录、文件名后缀和相对路径，停止前复核 PID 与创建时间。搬迁后仅在“开启定时关机”的重新登记流程中，按原计划任务的完整脚本路径接管旧倒计时。隔离 PowerShell 测试模拟进程查询与终止，覆盖路径边界和显式旧路径接管；未操作真实倒计时或计划任务。

### 已修复 P2：大纲未保存时的退出保护

位置：`ProjectsPage::saveOutline`、`MainWindow::quitApplication`。

主窗口关闭退出和托盘退出均先保存大纲；失败则阻止退出、打开大纲并保留编辑内容，恢复数据库后可重试。数据库初始化失败时仅显示说明页，不创建编辑页面或自动化入口，失败连接关闭。测试在隔离库用 SQL 触发器拒绝写入，验证两种退出路径均不丢失内容，解除故障后关闭可以保存；损坏数据库验证无编辑入口。顺带修复项目可选目录/大纲为空时误绑定 SQL NULL 的问题。

### 新增：项目删除双击与名称确认

单击“删除项目”不触发删除；双击弹出确认窗口，必须完整输入“我确认删除（项目名称）”，中文全角括号、项目名和空格精确匹配，确定按钮才启用。提交处理再次校验，错误输入无法绕过按钮保护；取消和重新打开不会沿用上次输入。删除仅影响数据库中的项目、大纲和关联工作记录，不删除项目目录文件。界面测试覆盖单击、错名、空输入、多余空格、错误括号、绕过按钮直接提交、取消、精确确认、其他项目及目录文件保留；截图为 project-delete-confirmation.png。

## 当前能力边界

- 尚无 WSL 专用执行器、自动调度业务、终端交互、全局异常角标、日志/产物浏览、通用取消命令和完整历史运行记录。
- 同一工具互斥只存在于一个客户端进程内，不能代替工具自身的跨进程锁与幂等性。
- 关闭到托盘与完全退出不同；不承诺完全退出后客户端启动的子进程继续运行。
- 项目名称和目录、大纲/日记正文、提醒日期、集合排序等主要流程有现有回归覆盖；不能由此推断任意规模数据下的性能和所有故障恢复均已验证。
- 工作区中的 `Python/`、`%SystemDrive%/` 是未跟踪的本机运行时/环境目录，本轮未修改或打包；它们不应被误认为应用必需源码。发布应使用干净构建输出。
