# v3.2.0 日常操作与后台资源审查

审查对象为浅色工作台相对 v3.1.0 的改动，以及用户验收后精简的日历、项目和侧栏操作。重点是普通日常操作；不把数千条内容的批量转移作为本次优化目标。

## 稳定性

检查全局主题安装、窗口显示事件、空列表提示的父子关系、项目状态与右键设置回调、大纲按钮键盘处理、保存状态和窗口销毁路径。本轮未发现需要阻止发布的新崩溃问题，也没有为假设中的极端输入扩大改造范围。

- 全局主题只安装一次；显示事件中应用标题栏与按钮样式，不增加持续计时或重绘任务。
- 空内容提示由列表视口持有，随视口销毁，且不拦截点击与拖放；没有加入伪数据行。
- 项目右键设置先切换到目标项目，保存失败阻止切换时不会误打开另一项目的设置；项目状态只在数据库写入成功后更新。
- 大纲、协作记录、日记、提醒沿用原有保存及退出保护；菜单移动没有绕过删除确认。
- 原生 Windows 现场检查了项目切换和含公式大纲打开；公式正常渲染，进程没有崩溃。

完整 **22 个 CTest 套件全部通过，69.79 秒**。包含记录阅读/编辑、保存与取消、项目设置和删除保护、剪贴板监听与复制、排序、公式切换及进程退出、启动、数据库、工具接入、便携更新和任务恢复。测试使用合成数据与模拟任务，不执行真实关机或外部业务。

## 后台开销

Windows 11 / Qt 6.11.2 / MinGW 13.1，本机 Release 构建。旧版和新版均使用独立目录、3 个合成项目、15 条协作记录、30 条剪贴板内容；禁用全局快捷键与自动更新请求，不读取正式版数据库。

原生旧版收起至托盘；新版在打开项目及公式大纲后退到后台，保留大纲窗口。另以 offscreen 隔离剪贴板运行新版并开启监听，避免采集用户系统剪贴板。各采样约 90.6 秒，每 5 秒记录一次：

| 场景 | 累计 CPU 时间增量 | 私有内存末值 | 私有内存变化 | 工作集末值 | 子进程 |
| --- | ---: | ---: | ---: | ---: | --- |
| v3.1.0 原生托盘空闲 | 0 ms | 28.61 MiB | -0.074 MiB | 67.12 MiB | 未观察到 |
| v3.2.0 原生后台，含已打开大纲 | 0 ms | 35.46 MiB | -0.195 MiB | 79.21 MiB | 未观察到 |
| v3.2.0 隔离剪贴板监听，空闲 | 0 ms | 13.85 MiB | 0 MiB | 37.46 MiB | 未观察到 |

CPU 数值是 Windows 累计进程计时的采样结果，不表示任意时刻绝对没有执行。原生两组打开窗口与缓存状态不同，不把内存差值归因于主题；offscreen 与原生内存也不直接横比。采样期间私有内存和句柄均未持续增长，公式完成后没有常驻子进程。

源代码确认：剪贴板仍由复制事件触发，采用 30 ms 单次防抖；隐藏页面不重建剪贴板列表。提醒与工具到期检查沿用 30 秒间隔，工具读取遵循各自启用的刷新策略；自动更新按日调度。此次视觉改造没有新增后台轮询、动画或常驻渲染服务。

结论：常规操作及本次有限时长的后台采样未发现阻塞发布的问题，空闲开销保持轻量。高频外部工具、自定义刷新、实际网络与长时间运行的耗用仍由具体工作负载决定；本轮没有做长期泄漏保证。

测试、采样脚本和完整原始结果按仓库约定保留在本地忽略目录，发布包从干净的 Git 提交生成，排除个人数据、状态、测试与构建缓存。
