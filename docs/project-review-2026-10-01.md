## 待处理发现

### [P1，已修复] 修改已停用的关机任务时，可能意外重新启用

位置：app/tools/scheduled-shutdown/shutdown-lib.ps1，Set-ShutdownTask（以下先记录原问题，随后说明修复）。

重新登记任务会使它启用。代码随后调用 Disable-ScheduledTask 恢复用户原来的停用选择，但使用 -ErrorAction SilentlyContinue；若该操作失败，函数仍正常返回新的（已启用）状态。用户仅修改时间或倒计时，却可能导致原来关闭的定时关机重新生效。

证据：已用本地 Review-ShutdownDisabled.ps1 完全模拟任务调度接口，注入恢复停用时的权限错误，复现“函数正常返回、任务保持启用”。没有读取或修改真实计划任务，也没有运行关机命令。

修复：读取原状态失败（除明确不存在之外）或状态未知时拒绝重新登记；所有注册及回退路径都使用 -Disable:$wasDisabled 创建任务设置，避免先启用再停用。登记后复核状态，异常时显式尝试停用并再次复核；任何无法确认停用的情况都报错并提示用户立即核对。最终状态快照也检查任务存在与停用状态，不再静默报告成功。

验证：新增本地 shutdown_task_settings 回归，15 个场景覆盖正常停用/启用、新建、读取失败、未知状态、注册回退、注册失败、异常启用恢复、停用权限失败、停用不生效、复核失败和最终状态变化；全部模拟任务接口。另确认本机 New-ScheduledTaskSettingsSet -Disable 生成 Enabled=false 的设置对象，未登记任务。

### [P2] 更新恢复记录采用直接覆盖写入，异常中断可能破坏恢复依据

位置：app/updater/Update-Orchestrate.ps1:13–14，Write-UpdateJson；调用包括 :170 和 :187 的 suspended-tasks.json。

WriteAllText 直接截断并重写原文件。在已暂停部分任务后，下一次写日志期间断电、进程中断或磁盘写入失败，可能留下空文件或不完整 JSON，损坏先前有效的任务恢复记录。同样影响 update-result.json 的清理重试依据。新清理逻辑对无效记录会保守保留文件，但无法从损坏日志自动恢复任务信息。

证据类型：静态故障路径审查；本轮没有进行真实断电测试。

建议：先在同目录写入临时文件、完整落盘后再原子替换正式记录，失败保留原记录；首次创建与替换分别处理，并增加中途写失败、替换失败和旧记录保留测试。

### [P2] SSH 工具声明导入仍同步阻塞主界面

位置：app/src/pages/automationpage.cpp:1591–1600、:1868–1877。

注册服务器工具和重读声明调用 runSshCapture，在界面线程 waitForStarted(5000) 和 waitForFinished(30000)。网络迟缓、SSH 登录脚本挂起或读取声明阻塞时，主窗口无法及时响应，日历提醒定时器也受阻。该问题不等同于状态刷新：状态读取主流程已经使用异步进程。

证据类型：调用链静态核对；本轮没有连接真实 SSH 主机。另见本地 readAll 和远程 cat 的声明读取目前缺少明确的字节上限，适合在异步改造时一并补齐。

建议：复用异步状态读取的超时/取消和分块限流模式，提供导入进度与错误状态。

## 本次修改及安全边界

- 新版启动确认且 tasks_restored=true 后才删除本次完整备份，再清理更新工作目录。
- 使用安装目录对应的独立清理互斥锁，串行化更新与后台清理，避免相互覆盖结果；不干扰应用自身运行锁。
- 精确检查备份同级目录、安装名、日期/随机后缀、旧版身份和当前版本。拒绝根目录、安装目录、其他安装备份、符号链接/目录联接及链接父目录。
- 未恢复任务日志、损坏日志、更新失败或证据不足时保留恢复材料。
- 文件占用时保留身份信息和 cleanup_pending，后续启动可重试；清理失败不会被记为更新失败。
- 兼容旧更新器已经清理工作目录的情形：仅依据最近一次成功结果补清其精确对应备份，不遍历删除所有历史 backup 文件夹。
- 回滚成功后旧版数据已回到安装目录；失败工作目录仍保留，不额外删除恢复材料。
- 数据库迁移快照 data/backups 不属于整包回滚备份，本轮不改其保留规则。
- 主窗口安装确认提示、更新结果说明、客户端 README 和便携包 README 已同步。
