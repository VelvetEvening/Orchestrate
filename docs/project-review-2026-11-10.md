# v3.1.0 公式预览验收

本次改动只扩展记录的标题预览，不迁移数据库、不更改保存格式。日记、提醒、大纲和协作记录正文／摘要仍通过 `HeadingTextEdit` 读取和编辑纯文本。

## 崩溃与资源边界

- MicroTeX 与字体只链接到单独的 `OrchestrateMath.exe`，不加载进主程序。主程序通过 Qt 的异步进程信号读取结果，没有同步等待公式排版。
- 每次请求先防抖 80 ms；换记录、修改文本、进入编辑或关闭窗口时取消未完成的渲染。渲染完成即退出，没有空闲轮询或常驻数学服务。
- Windows Job Object 限制子进程内存为 192 MiB，并在所属预览释放时结束进程；请求超时为 5 秒。输入、命令、嵌套、公式数量、像素尺寸、输出及缓存均有限制。
- 禁用宏定义、文件引用和运行时配置命令。不完整或不支持的公式按原文展示；进程崩溃、缺失、失败和超时不修改正文。
- 公式对象的复制转换回原始 LaTeX，缩放和异步替换通过文本位置映射保留选择与阅读位置。

## 本地检查

环境：Windows 11、Qt 6.11.2、MinGW 13.1、Release 构建。沿用 `app/build-qt` 和隔离测试数据库，未使用个人数据库、真实自动化任务或全局快捷键。

- 完整 22 个 CTest 套件通过，最终全量运行耗时 70.41 秒。之后对进程取消／启动失败清理和同目录部署规则的调整，再跑公式专项通过。
- 公式专项 8 passed / 0 failed，覆盖四种分隔符、代码块、反引号、金额、转义、缩进的多行公式、实际注意力公式、中文、矩阵、复制、缩放、快速切换、非法命令、强制结束渲染进程及恢复。
- 30 次连续更换公式后，主进程私有内存未持续增长；最后一次专项测得较预热后减少约 2.1 MiB。1.5 秒空闲 CPU 采样为 0–15 ms；普通文本不再保留渲染进程。
- 含多个公式的首次预览约 0.8–1.4 秒，异步期间界面保持响应；18 万字符普通文本预览约 0.55 秒；10 万反斜杠扫描低于 1 ms。时间会随设备和字体缓存变化。
- 用已初始化的隔离便携数据库比较 v3.0.2 与 v3.1.0 空闲主程序（offscreen，未加载个人内容）：私有内存约 14.45 / 14.42 MiB，工作集约 37.91 / 37.85 MiB；3 秒采样的 CPU 增量均为 0，内存没有增加，没有子进程。
- 检查 900×680 与 480×440 的预览截图；修复小字号数学字体的细笔画显示，复制后不出现对象替代字符。

测试和截图按仓库既有规则保留在本地 `app/tests`、`app/build-qt/tests/math-preview-test`，不随源码或发布包分发。检查能覆盖常规使用和选定故障路径，不能证明任意公式、全部字体与所有 Windows 环境都不存在问题。

## 发布约束

便携包必须含 `OrchestrateMath.exe`、Qt Windows 插件、MicroTeX／字体和 tinyxml2 许可；打包脚本会检查这些文件。资源随二进制内嵌，不依赖工作目录、网络或本机 TeX。数据库继续使用 schema v7。
