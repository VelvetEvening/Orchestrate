# Orchestrate 工具接入与适配指南（v1）

面向准备接入 Orchestrate 的工具作者、维护者和负责适配的开发代理。本文描述 **2026-09-29 工作树的实现**；字段值、执行限制与样例均以本版本为准。旧 ADR 记录设计取舍，不代表其中所有设想都已实现。

## 1. 先明确交付物和职责

一个适配完成的工具应交付：

1. 一份 `orchestrate-tool.json`，声明身份、目标、状态文件和允许用户运行的命令。
2. 一个稳定的 `state/current.json`，报告最新业务状态。
3. 有限时长、无需终端交互的命令入口，以及工具自身的安装、认证、运行依赖说明。
4. 一份验收记录，覆盖成功、失败、重复执行、路径和状态刷新。

Orchestrate 保存注册关系、分组及刷新偏好，读取状态文件，并按用户操作启动已声明命令。工具负责业务、凭证、调度器、进程管理、日志、状态生成及权限。**外部工具不应直接读写 `data/orchestrate.sqlite3`。**

工具目录由你维护，Orchestrate 不复制或上传它。不要把普通第三方工具放进客户端程序旁的 `tools/`：那是内置工具区，启动会自动同步声明并赋予不可移除的内置身份。第三方工具应放在自己的目录，再通过界面注册。

## 2. 选择接入方式

| 场景 | 声明与入口 | 当前支持范围 |
| --- | --- | --- |
| Windows 本机工具 | `target_type: "windows-local"`，注册本地工具 | `QProcess` 启动程序，支持参数表单 |
| POSIX 服务器工具 | `target_type: "ssh"`，注册服务器工具 | 系统 OpenSSH、非交互认证、远端 POSIX shell 和 `cat` |
| 已由计划任务或其他系统运行，只需展示 | 按所在地选上面一种；`commands: []` | 由外部生产者写状态，客户端只读 |
| WSL 专用目标 | 暂不支持 `target_type: "wsl"` | 不要声明一个未实现的目标；若自建 Windows 包装程序调用 WSL，路径转换和状态同步均由包装程序负责 |
| 需要密码输入、终端问答或交互式 shell | `interactive: true` | 可以登记，但客户端会阻止直接启动；在客户端外完成初始化/登录 |
| 长驻服务 | 声明短时的启动、停止、同步状态命令 | 不要让启动命令一直占着服务前台；长期运行由服务管理器/调度器负责 |

注册不会自动运行安装、登录、启用计划任务或业务命令。`high_risk` 是工具作者提供的确认标记，不是程序权限隔离或自动风险识别。

## 3. 十分钟跑通最小样例

可直接复制 [完整样例目录](examples/tool-adapter/README.md)，其中包含 Python 标准库适配器、本地声明、SSH 声明和只读声明。Python 3.9+ 即可。

```text
my-tool/
  orchestrate-tool.json
  adapter.py
  state/
    current.json          # 运行时生成；不要随发布包分发个人状态
```

在复制后的目录运行：

```powershell
python -u adapter.py run --message "你好 Orchestrate" --count 2
python -u adapter.py fail
```

第一条应退出 0 并生成 `success`；第二条故意退出 1 并把状态更新成 `failure`。接着在 Orchestrate → 自动化工具 → 注册本地工具中选择声明。双击命令行运行，观察参数表单、最近运行输出和状态明细。

示例 `executable` 为 `python`。正式接入建议改成实际解释器的绝对路径，例如 `D:/Tools/my-tool/.venv/Scripts/python.exe`。桌面启动的客户端未必具有终端里激活的虚拟环境或最新 PATH。

## 4. 声明字段完整约定

JSON 使用 UTF-8，建议无 BOM；不得含注释、尾随逗号、NaN 或 Infinity。布尔值用 `true`/`false`，不是字符串 `"true"`。文件名建议统一为 `orchestrate-tool.json`，解析并不依赖文件名。

| 字段 | 类型 / 必填 | 含义与默认行为 |
| --- | --- | --- |
| `schema` | 字符串，必填 | 精确为 `orchestrate-tool/v1` |
| `id` | 非空字符串，必填 | 稳定机器标识，推荐 `daily-signin` 形式的小写英文、数字、连字符；不要每次发布或改显示名就换 ID |
| `name` | 非空字符串，必填 | 界面名称，可修改 |
| `description` | 字符串，可选 | 工具用途，缺省为空 |
| `group` | 字符串，可选 | 已存在的全局工具组名称，不会自动新建组 |
| `target_type` | 字符串，必填 | 本地入口精确为 `windows-local`，服务器入口精确为 `ssh` |
| `working_directory` | 字符串，可选 | 命令的工作目录，路径规则见下一节 |
| `state_path` | 非空字符串，必填 | 最新状态文件位置；即使 `commands` 为空也要声明 |
| `commands` | 对象数组，可选 | 缺省或 `[]` 表示只读监测；每个对象是一条命令 |

未知字段目前不生效；不要依靠自己加的 `env`、`timeout`、`schedule`、`heartbeat_timeout`、`artifact_directory`、`ssh_host` 或 `builtin` 字段触发客户端能力。SSH 主机在注册界面填写，内置身份由客户端管理。

**身份与更新：**客户端以 `id` 与注册时填写的 SSH 主机字符串识别同一工具。本地的主机字符串为空；两个本地副本如果 ID 相同，会更新同一条注册。相同服务器使用两个不同 SSH 别名也会被视为不同注册。不要仅靠目录区分实例；确需多实例时，分别设置 ID 和状态路径，并同步其 `tool_id`。

**原子保存：**首次注册、重复导入、重新读取声明及内置工具同步，均把工具资料和命令列表放在同一个数据库事务内。任何一步写入失败都会回滚，保留原资料与原命令；首次失败不留下半注册工具。解析成功后仍可能发生存储失败，请按客户端错误提示处理。

第一次注册时，当前选中的具体工具组优先，其次匹配声明中的 `group`，最后放入“未分组”。重新导入相同身份的声明会确认更新；“重新读取声明”也会替换工具资料及整套命令。自定义分组、周期刷新偏好、内置身份保留。修改 JSON 后要重新读取声明，单击“刷新状态”不会刷新命令定义。新命令列表替换旧列表，不是追加。

## 5. 路径和执行环境：适配最容易出错的地方

| 位置 | 本地 Windows | 服务器 SSH |
| --- | --- | --- |
| 声明文件 | 文件选择器选中的路径 | 注册时输入以 `/` 开头的远端绝对路径 |
| 未写 `working_directory` | 声明所在目录 | 声明所在目录 |
| 相对 `working_directory` | 相对于声明所在目录 | 不允许；必须为 POSIX 绝对路径 |
| 相对 `state_path` | **相对于声明所在目录** | **相对于 `working_directory`** |
| 脚本参数里的相对路径 | 由被调用程序按照工作目录解释 | 同左，工作目录先经远端 `cd` 设置 |
| `executable` | 推荐绝对路径；简单程序名通过 Windows 进程环境查找 | 绝对路径或远端非交互 shell 可找到的程序名；本目录程序使用 `./tool` |

本地示例：声明在 `D:/Tools/report/orchestrate-tool.json`，`working_directory` 写 `worker`，`state_path` 写 `state/current.json`。运行目录是 `D:/Tools/report/worker`，读取的状态却是 `D:/Tools/report/state/current.json`。如果脚本把状态写在 `worker/state/`，界面就不会读到它。建议让适配器以自身脚本位置计算状态路径，或明确传入绝对路径。

本地 JSON 路径优先使用 `/`；使用反斜杠必须写成 `\\`。服务器只用 `/`，不使用 Windows 盘符、反斜杠、`~` 或 `$HOME` 来表示声明/工作/状态路径。客户端不会帮这些字段做环境变量或波浪号展开。

每个 `arguments` 元素就是一个参数。例如：

```json
{
  "name": "执行报表",
  "executable": "D:/Tools/report/.venv/Scripts/python.exe",
  "arguments": ["-u", "worker/run.py", "--output", "D:/Reports/本周 报表"]
}
```

不要给含空格的元素再手工加引号；不要把整条命令塞进 `executable` 或一个 `arguments` 元素。程序与参数分开传递，本地默认不经过 shell，`&&`、`>`、管道、通配符和 `%VAR%` 不会自动成为 shell 操作。`.ps1` 应声明 `powershell.exe`/`pwsh.exe` 加 `-NoProfile -NonInteractive -File script.ps1`；`.py` 声明 Python 解释器。确需 shell 的脚本由你显式声明解释器，并负责它的转义和输入安全，优先使用固定脚本文件而非拼接脚本文本。

命令启动继承客户端环境；不自动激活 Conda/venv，不切换系统用户，不提权。凭证应由工具通过环境、系统凭证存储或私有配置读取，**不要放在参数默认值、状态文件或日志中**：实际命令行和输出会出现在最近运行面板，当前没有密码输入控件或自动脱敏。

### SSH 准备与故障定位

1. 在客户端电脑安装可从 PATH 找到的 OpenSSH `ssh`。
2. 在客户端外完成首次主机密钥确认、密钥/agent 配置，并确认 `ssh -o BatchMode=yes my-server true` 成功。
3. 端口、用户名、IdentityFile、代理跳转等写在自己的 `~/.ssh/config`，注册时填 `my-server`，不要把 `-p 2222` 之类选项拼到主机字段。
4. 将工具及依赖自行部署到远端。验证 `ssh my-server 'cat /opt/my-tool/orchestrate-tool.json'` 和声明中的工作目录、解释器。
5. 选择“注册服务器工具”，填写别名和远端声明绝对路径。不要通过本地导入入口注册 `target_type: "ssh"`。

客户端传入 `BatchMode=yes`、`ConnectTimeout=10`，命令参数逐个按 POSIX shell 规则转义，然后 `cd` 和 `exec`。不会为你申请伪终端、发送密码或打开登录 shell；不要依赖交互式 shell 配置加载的 PATH。远端应有 POSIX shell 与 `cat --`，目前不保证 Windows SSH 服务端兼容。

注册/重读声明使用同步 SSH 读取，启动等待最多 5 秒、命令完成等待最多 30 秒，期间界面可能等待；日常 SSH 状态读取在后台，从启动起设 30 秒总超时。超时会结束本次本地 SSH 读取、清理“读取中”并显示错误，可以再次刷新。`state_path` 应指向普通文件，不要使用 FIFO 或设备。

## 6. 每条命令的字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `name` | 非空字符串，必填 | 界面显示名，建议在同一工具内唯一 |
| `executable` | 非空字符串，必填 | 程序/解释器，不是完整命令行 |
| `description` | 字符串，可选 | 用途、影响和前置条件 |
| `arguments` | 字符串数组，可选 | 缺省 `[]`；整数参数也写成字符串，例如 `"5"` |
| `parameters` | 对象数组，可选 | 运行前表单定义 |
| `interactive` | 布尔值，可选 | 缺省 `false`；`true` 会阻止直接运行 |
| `high_risk` | 布尔值，可选 | 缺省 `false`；删除、关闭系统等命令由作者明确标记 |

本版本会拒绝非对象命令、空名称/程序名、非字符串参数、错误的数组类型、字符串形式的风险标记和无效参数定义。不会再静默跳过错误命令后把残缺声明注册成功。

同一工具注册在**一个客户端进程内**同时只能运行一条命令；不同工具可以并行。此限制不是跨进程锁，不覆盖外部调度器、其他客户端或另一个本地副本。客户端完全退出后不承诺其子进程继续运行，也没有通用的命令取消按钮、整体运行超时或历史运行数据库。运行面板按 UTF-8 连续解码，支持中文字符跨读取块；每个工具最近运行只保留末尾 256 Ki 个 UTF-16 代码单元（最多约 512 KiB 文本），截断有明确提示，连续输出期间最多每 100 毫秒重绘一次。完整日志应由工具自行写入文件。命令应及时结束；持续任务交给服务/调度器，另设能及时返回的控制命令。

## 7. 参数表单与替换规则

完整可运行例子见 [本地声明](examples/tool-adapter/orchestrate-tool.json)。下例展示时间与选项类型，实际脚本须实现对应参数：

```json
{
  "name": "更新配置",
  "executable": "python",
  "arguments": ["configure.py", "--time", "{time}", "--mode={mode}"],
  "parameters": [
    {"key": "time", "label": "执行时间", "type": "time", "default": "08:30", "state_key": "settings.time"},
    {"key": "mode", "label": "模式", "type": "choice", "default": "safe", "options": [
      {"value": "safe", "label": "稳妥"}, {"value": "fast", "label": "快速"}
    ]}
  ]
}
```

| 字段 | 适用范围 | 行为 |
| --- | --- | --- |
| `key` | 所有类型，必填 | 同一命令内唯一；只用英文字母、数字、`_`、`.`、`-`；首尾空格会被裁掉，建议直接用规范名称 |
| `type` | 所有类型 | `string`（缺省）、`integer`、`time`、`choice`、`boolean`；类型名会转为小写 |
| `label`、`description` | 所有类型 | 显示标签和说明；label 缺省使用 key |
| `default` | 所有类型 | 默认值；应与类型一致 |
| `state_key` | 所有类型 | 从**已缓存的状态**读取点分对象路径，存在且非 null 时优先于 default；不支持数组下标或含点的键名 |
| `required` | 所有类型 | 标星；当前仅对 string 做非空校验，其他类型的控件始终有值 |
| `placeholder` | string | 空输入框提示 |
| `min`、`max`、`step`、`unit` | integer | 缺省为 0、1000000、1、无单位；单位仅显示，不传入命令 |
| `options` | choice，必填非空数组 | 推荐字符串或 `{"value":"safe","label":"稳妥"}`；对象 value 也可为数字/布尔标量，会转换为文本 |
| `text` | boolean | 复选框文字 |
| `true_value`、`false_value` | boolean | 勾选/未勾选时传入的字符串，缺省 `"true"`、`"false"` |

填写结果：string 会裁掉首尾空白，integer 是十进制文本，time 固定为 `HH:mm`，choice 传 value，boolean 传相应映射值。若需要保留用户文本首尾空格，不要使用当前的 string 表单作为无损文本编辑器。

应显式提供合法默认值：integer 控件会把越界值夹到范围，非法数字回退到最小值；非法时间回退到 `00:00`；choice 默认值不匹配时选第一项；boolean 只有 JSON `true` 或字符串 `"true"` 会勾选。`state_key` 不会在打开表单时强制同步远端；涉及关键配置时，先刷新并等待完成，再打开表单。客户端不替工具验证业务规则、整数上下界定义或状态默认值的业务合理性，脚本必须自行校验。

替换仅作用于 `arguments`，不作用于 executable、路径字段或环境：

- `"{name}"` 替换成一个参数，含空格也不拆分。
- 整个元素为 `"{key}"` 且结果为空时，移除这一个元素。例：boolean 的 `false_value: ""` 用来省略开关。
- `"--name={name}"` 在元素内替换；结果为空时仍传 `"--name="`。
- 未定义的 `{key}` 原样保留；填写的值不会被当作新模板递归展开。
- **不会连带移除前一个元素**。`["--name", "{name}"]` 配合空值会留下孤立的 `--name`，应改用 `--name={name}`、非空必填参数或工具支持的开关形式。
- 字面量 `""` 作为空参数保留。本版本用 JSON 数组存储参数；旧版注册中已丢失的空参数需重新读取原声明恢复。

高风险命令有参数时，表单内风险说明和“确认运行”按钮就是确认步骤；没有参数时使用单独确认框。参数表单取消后不启动程序。

## 8. 状态生产协议

状态由工具写入 `state_path` 指向的普通文件。客户端**不会从 stdout 自动抓取 JSON 作为状态**，也不会调用名为 status 的命令代替读取。只打印 JSON、不写文件，不算完成接入。

新适配器应遵循以下生产约定：

```json
{
  "schema": "orchestrate-state/v1",
  "tool_id": "daily-signin",
  "current_date": "2026-09-29",
  "updated_at": "2026-09-29T09:30:00+08:00",
  "result": "partial_success",
  "summary": "2 个站点中 1 个成功，1 个需要重新登录",
  "last_command": "run",
  "items": [
    {"name": "site-a", "result": "success", "summary": "签到成功"},
    {"name": "site-b", "result": "failure", "summary": "登录失效"}
  ],
  "settings": {"mode": "safe"}
}
```

| 字段 | 生产者约定 | 客户端当前如何使用 |
| --- | --- | --- |
| `schema` | 必填字符串 `orchestrate-state/v1` | 本地与 SSH 读取都强校验，不匹配则读取失败 |
| `tool_id` | 必填，与声明 `id` 一致 | 精确匹配当前工具，拒绝误用其他工具状态 |
| `result` | 必填非空字符串 | 显示状态文字及颜色 |
| `summary` | 必填简短字符串 | 显示摘要；空值提示未提供摘要 |
| `updated_at` | 必填，带时区 ISO 8601 时间 | 校验格式并转换为客户端本地时间显示 |
| `current_date` | 必填，`YYYY-MM-DD` | 校验有效日期；业务周期由生产者定义，不默认等于今天 |
| `expires_at` | 可选，带时区 ISO 8601，不能早于 updated_at | 到期后标为“已过期”，不再显示顶层成功；省略则不推断业务有效期 |
| `last_command` | 建议提供稳定业务操作标识 | 不关联命令数据库 ID，也不自动改变最近运行面板 |
| `items` | 可选对象数组；每项 name/result/summary 字符串 | 逐行展示明细；子项不会自动汇总顶层 result |
| `settings` 等自定义对象 | 可选 | 可以通过 state_key 读取默认值，未配置的字段不专门展示 |
| `artifacts`、`logs`、`heartbeat` 等 | 可选扩展，结构由工具维护 | 当前没有通用产物打开、日志读取或心跳健康检查 |

客户端强校验基础字段、类型、工具归属、有效日期、带时区时间，以及可选 items 的结构。空对象、错误 schema、其他工具的 JSON 都会读取失败并清除此前缓存，不能继续冒充成功。客户端仍不验证业务结论是否真实；工具自身应覆盖业务规则、跨进程并发和故障上报测试。

`expires_at` 是向后兼容的可选字段，由工具按业务周期或心跳要求计算。例如每天有效的结果可声明次日零点失效，常驻服务可声明下次心跳的截止时间。客户端也检查缓存中的有效期，即使自动读取关闭，仍会在后台检查时更新“已过期”（最多约 30 秒延迟）；打开详情或重新读取时立即计算。过期只影响显示，不改写原始 JSON。未声明时不对所有工具套用固定超时。

### result 的显示语义

| 值 | 展示 | 建议使用场景 |
| --- | --- | --- |
| `success` | 成功，绿色 | 本次业务完成 |
| `already` | 已处理，绿色 | 幂等执行发现本周期已完成；历史 ID `daily-check-in` 会显示“今天已签到” |
| `partial_success` | 部分成功，黄色 | 一部分子任务失败，顶层由生产者汇总 |
| `failure` | 失败，红色 | 业务失败，summary 应说明下一步 |
| `running` | 运行中，蓝色 | 工具报告正在运行，不能据此推断客户端仍持有进程 |
| `skipped` | 跳过，灰色 | 明确决定不执行 |
| `disabled` | 已停用，灰色 | 工具的调度/服务被关闭 |
| `unknown` | 未知，黄色 | 生产者无法确认当前情况 |
| `none` | 暂无状态，灰色 | 通常由本地文件缺失时的客户端占位生成，不建议当业务结果 |

未知字符串原样显示为黄色。只有工具行显示当前结果和颜色；尚无全局/组级异常角标、已读清除或异常通知机制。不要依赖未实现的“跨天自动变逾期”“心跳失联自动变红”。

### 退出码、运行状态与业务状态是两条线

最近运行面板由子进程退出结果决定：正常退出 0 为完成，非零或崩溃为失败。状态卡片始终来自 JSON。退出 0 不会把 JSON 自动改成 success，退出 1 也不会覆盖旧 success。

短任务应在开始时写 running，在业务结束时写最终状态，再退出；异常处理应尽量写 failure 后以非零退出。若写入失败，必须在 stderr 清楚报错并非零退出，避免只显示旧成功。建议 partial_success 返回非零，让最近运行也能提示关注；幂等 already 通常退出 0。若命令启动了独立服务后立即返回，返回 0 只表示启动请求完成，持续状态由外部服务维护。

## 9. 状态更新、刷新与并发

- 客户端启动、选择工具详情、手动刷新、命令结束及启用后的周期刷新会读文件；关闭窗口到托盘后仍可刷新，完全退出则停止。
- 周期刷新默认关闭。间隔刷新最小 1 分钟；内部约每 30 秒检查是否到期，因此不承诺秒级准点。每日刷新使用客户端本地时间，不是服务器时区。
- **刷新不会触发业务命令，也不会调用“从系统同步设置”之类工具命令。**外部设置变化时，需工具的生产者主动写状态，或用户运行工具声明的同步命令。
- 本地文件尚不存在时显示“暂无状态”；本地存在但无权限/JSON 损坏显示读取失败。SSH 使用 `cat`，远端文件不存在也显示读取失败，当前没有统一成暂无状态。
- 外部命令结束后才写状态，会错过客户端结束时的那次读取；应先原子更新，再退出。如果由分离的服务稍后更新，启用适当刷新或手动刷新。
- `current_date` 是结果所属的业务周期，`updated_at` 是这份快照更新时间。读取文件时不要把昨天的成功伪装成今天。过期阈值、预期运行时间、心跳新鲜度由工具按业务计算，并体现在 result/summary 中。
- 原子替换保证读者看不到半个文件，**不解决多个生产者覆盖**。手动运行与外部计划任务可能并发，需要工具自身的锁、单一状态发布者或明确合并规则。不要靠客户端单工具互斥代替业务锁。

原子写法参考 [adapter.py](examples/tool-adapter/adapter.py)：在状态文件同目录创建唯一临时文件，UTF-8 写完整 JSON，flush/fsync 并关闭，再 `os.replace` 替换目标，失败后清理临时文件。不要先清空正式文件再逐步写入，也不要从另一磁盘移动临时文件。Windows 上需确保读写者及时关闭文件，并对被占用时的替换失败采取有限重试/错误报告。

状态是小型摘要而不是日志库。客户端限制状态 JSON 不超过 1 MiB、items 不超过 500 项；SSH 状态读取的 stderr 也限制为 1 MiB。超过限制显示读取失败并允许重试，完整日志另存由工具管理。

## 10. 逐项验收

| 检查 | 预期 |
| --- | --- |
| 在客户端外运行相同 executable + arguments | 无需问答，解释器、权限和依赖已就绪 |
| 从含空格/中文目录运行；改变启动工作目录 | 脚本仍写到声明的正确 state_path |
| 首次注册和重启 | 一条工具注册；状态读取不触发业务 |
| 重复导入、修改命令后重新读取 | 命令整体更新，分组和刷新偏好保留 |
| 成功、失败、部分成功、already | 退出码与 JSON 明确对应；失败覆盖旧成功 |
| 参数的最小/最大值、空开关、空格、中文、单引号、花括号 | 到脚本的 argv 与预期一致，非法业务值被脚本拒绝 |
| 修改外部设置后刷新 | 只反映已经写入的状态；需要时先执行同步命令 |
| 状态缺失、损坏、权限不足、tool_id 错误 | 本地缺失显示暂无状态；损坏、错误归属和无权限不得显示旧成功 |
| 跨日、错过一次计划任务、生产者崩溃 | 工具能区分历史成功与当前未知/失败，不能只更新时间造成功 |
| 手动与外部调度同时触发 | 锁和幂等规则有效，不覆盖另一运行结果 |
| SSH 断网、认证失效、远端程序不存在 | 有明确错误；恢复连接后可再次读取/运行 |
| 文件修改、工具搬家、移除注册 | 重读/重新导入恢复路径；移除不删除文件、不停止服务、不卸载调度 |

测试关机、删除等真实业务前，应先提供干运行或模拟入口。不要拿内置定时关机的“立即关机”作为通用接入连通性测试。

## 11. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| JSON 可打开但注册失败 | schema、入口与 target_type、数组类型、布尔类型、每条命令的非空字段 |
| 显示暂无状态/文件不存在 | 是否只打印了 JSON；本地 state_path 是否误按 working_directory 计算 |
| 命令能在终端跑，界面启动失败 | PATH/虚拟环境、相对 executable、权限、脚本所需工作目录 |
| 命令退出成功但显示旧状态 | 是否写错文件、先退出后写文件、外部业务失败却未更新 JSON |
| 参数表单默认值过时 | 缓存状态是否已刷新完成；工具是否先同步系统真实配置 |
| boolean 未选中后脚本报参数缺失 | 是否留下 `--option` 而只删除了它的值 |
| 新字段/新命令不出现 | 是否用了“刷新状态”而不是“重新读取声明”；当前版本是否支持字段 |
| 服务器连接成功但读不到文件 | 非交互环境、绝对路径、POSIX 路径、远端权限与 stdout 是否被启动脚本污染 |
| SSH 读取超时 | 后台读取 30 秒后停止并清理占用；检查网络、认证和远端文件类型，再刷新重试 |
| 昨天 success 今天仍绿色 | 检查工具是否声明 expires_at；省略时由生产者维护业务周期状态 |

## 12. 交给另一个工具维护者的适配任务模板

> 请为此工具适配 Orchestrate v1。先阅读本指南，并以本仓库样例为参考。保留现有业务语义，增加稳定 ID 的接入声明和原子更新的最新状态文件。只登记用户应当直接运行的非交互命令；明确工作目录、依赖、凭证来源、真实退出码、状态路径及失败处理。参数由 parameters 定义，业务校验仍在脚本中执行。已有调度与长驻进程继续由工具自身管理，不把 Orchestrate 刷新当作调度。交付本地或 SSH 声明、适配入口、使用说明及上述验收记录；标明尚未实现的能力，不通过编造状态掩盖未验证结果。

若工具已有 CLI 和状态文件，优先做小型包装/格式转换；不要为接入而重写整套业务。任何超出本指南的字段或运行能力，先在 Orchestrate 中实现并测试，再作为新约定交给其他工具。
