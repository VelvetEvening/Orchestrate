# 顶部导航与页面布局调整

分支：`design/page-layout`，从已发布 v3.2.0 的 main 创建。本轮交付为可验收的分支版本。

## 用户反馈与方向

去掉侧栏重复的应用名后，原来的折叠箭头单独占一行，留下了突兀的空白。用户以 Codex 顶部的分栏按钮作为交互参考，同意把侧栏开关与当前页面标题合并在全局顶部，侧栏直接从导航开始。

用户进一步指出系统应用名与页面标题仍形成两层，并明确不需要顶部的 Orchestrate 标题。本轮属于 Operate 模式下的布局调整，保留灰白与雾蓝主题和五个模块功能，将主窗口内容扩展到窗口标题区域；页面开关、名称与右侧窗口按钮共同构成一条顶栏。展开侧栏仍为 216px，收起为 72px 图标栏；开关位于固定位置，切换状态时不横向移动。

## 实现边界

- 全局顶部使用分栏 SVG 按钮与 16px 当前页标题，移除五个页面原有的重复标题行。Windows 主窗口不再绘制应用图标和 Orchestrate 名称；任务栏与 Alt+Tab 保留应用识别信息。
- 顶栏采用系统标题区域高度（本机为 32px），不再叠加垂直留白。左边距为 18px，按钮与标题间距 12px；按钮图标为 18px，内容尺寸 28px，加边框后为 30px。
- Windows 采用 Qt 6.11.2 的 `ExpandedClientAreaHint`、`NoTitleBarBackgroundHint` 和 `CustomizeWindowHint`，右上角的窗口按钮与窗口交互交由 Qt Windows 后端处理。由于 QWidget 会自动补回 `WindowTitleHint`，窗口创建后仅在 QWindow 上关闭该绘制标记。顶栏为三颗窗口按钮预留系统标题高度的 4.5 倍宽度及 12px 间隔，剪贴板操作不会盖住它们。
- 正文保留左右 24px 边距，顶部改为 16px；侧栏首项同样距顶部 16px。
- 剪贴板的监听和历史设置移至顶部右侧，仅在剪贴板页可见；信号和状态仍归 ClipboardPage 管理。顶部历史设置按钮使用上下 4px 内边距，融入紧凑顶栏；独立使用该页面时，操作控件留在页面内。
- 原生键盘焦点顺序从顶部开关到当前页顶部操作，再到导航与正文；工具提示与可访问名称随展开、收起更新。
- 页面标题取固定模块名，不受设置入口的更新提示影响。不增加动画、定时器、网络请求或后台进程。

## 验证

- `app/build-qt` 完整构建通过，`builtin_acceptance`、`heading_text`、`clipboard`、`startup_visibility` 四组相关回归通过。
- 在 1180×760 和 980×640 下覆盖五个页面、展开和收起共 20 个组合，检查顶部按钮和标题坐标稳定、标题同步、侧栏首项位置及剪贴板顶部操作的显示范围。
- 验证 Tab / 空格键操作、监听开关持久化、历史设置弹窗打开与取消，以及设置有更新时页面标题仍为“设置”。导航沿用 Qt 排他按钮组习惯，Tab 进入当前选中项，方向键在组内移动。
- 已检查真实 Qt 截图中的空状态、项目数据、剪贴板预览和自动化长标题；用独立验收副本验证 Windows 原生窗口下展开与收起。副本位于 `app/build-qt/visual-review-preview/Orchestrate.exe`，使用既有合成数据。
- HTML/CSS 检测器不适用于此原生 Qt 项目；按源码核查共享样式、尺寸约束、控件生命周期及焦点顺序。本轮没有修改后台任务和监听调度。
- 标题区域融合后的四组相关回归重新通过（18.93 秒）。在 Windows 实机验证了顶栏拖动、双击最大化、还原按钮、最小化后恢复、边缘缩放到最小窗口、顶部历史设置打开与取消、侧栏收起，以及关闭后窗口隐藏但进程继续驻留托盘。
- 一体化顶栏的独立验收副本位于 `app/build-qt/integrated-header-preview/Orchestrate.exe`。桌面验证后重置了控制会话，并确认 `codex-computer-use.exe` 捕获辅助进程退出。
