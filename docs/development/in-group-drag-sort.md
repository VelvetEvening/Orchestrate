# 同层拖动排序

v2.4.0 新增功能。实现与交互验证来自 `feat/in-group-drag-sort`，基于 v2.3.2。

## 使用与边界

按住条目拖到目标条目的上半部或下半部，蓝色插入线分别表示放在目标之前或之后。也可选中条目后按 Ctrl+↑/↓。释放后立即保存顺序，当前选择、右侧详情和文件夹展开状态保持不变。

| 列表 | 可排序范围 |
| --- | --- |
| 项目列表 | 所有项目 |
| 自动化工具组 | 所有工具组之间，包括改过名的虚拟“未分组” |
| 自动化工具 | 同一工具组内，包括未分组工具 |
| 协作记录文件夹 | 同项目内，重点与普通文件夹分别排序 |
| 协作记录 | 同一文件夹内，或同一项目顶层的记录之间 |

跨组移动沿用右键菜单。重点文件夹继续置顶。搜索协作记录期间暂停拖动和快捷键排序，并显示清除搜索的提示；隐藏条目不会参与局部排序。

工具组和文件夹展开时，拖过其子项也能定位整组，放到该组之后；插入线跟随整组可见边界。普通工具或记录仍只能在原容器内排序。

## 保存方式

顺序存于现有 `app_settings` 的 `order.*` 键，值为同层条目的 ID 数组，不新增表或迁移，数据库继续使用 schema v6。未设置顺序时保留原有查询顺序；已有顺序的列表将未排过的条目追加到末尾。读取时忽略已删除或移出该层的 ID；移回原层的条目如果还在保存数组中，会恢复原位置。

工具组顺序中的 ID 0 代表虚拟“未分组”，保存时与实际工具组一起校验完整集合。只在工具树读取时包含这个虚拟组，工具登记和移动菜单仍沿用原有实体组接口。

保存事务核对当前层的完整成员集合，拒绝重复、缺失或跨层 ID。数据库保存成功后才移动界面条目；保存失败保留原有顺序和选择。排序不修改标题、摘要、正文、归属或内容时间戳。旧客户端仍能读取 schema v6 数据，只是不展示这些手动顺序。

树和列表共用 `SiblingOrderView`，拖放与键盘使用同一保存路径。树调整后同步清理 Qt 可访问行缓存，保留 v2.3.2 的折叠与搜索修复。

## 审查清单

1. 拖动工具组（包括改名后的“未分组”）到其他组之前或展开组的子项上，再调整同组工具顺序；切换页面后检查整组位置、子项顺序和工具详情。
2. 在项目文件夹内上下拖动记录，再调整项目列表及文件夹顺序；选中项和展开状态应保持。
3. 拖动重点文件夹时验证其仍在普通文件夹之前；尝试跨文件夹拖动应不改变归属。
4. 使用 Ctrl+↑/↓；搜索记录时应无法调序，清除搜索后恢复。
5. 重命名已排序条目、新增条目、完全退出并重开，检查顺序持久化。

本地预览使用正式数据的独立副本，排序不会写回正式数据。预览中的工具仍引用原注册的外部脚本，审查排序不需要运行工具命令。

## 已完成验证

开发构建通过；v2.4.0 发布前 20 个 CTest 套件全部通过（29.65 秒），其中 HeadingTextTest 为 67 passed / 0 failed。四个本地排序测试覆盖持久化、重命名与新增／删除、非法成员、数据库写入失败、搜索禁用、重点边界、选择与展开状态以及可访问行映射；追加的 `virtualToolGroupOrder` 覆盖改名后的“未分组”上下移动、完整集合校验、子项保留和重开恢复。

测试按仓库现有约定保留于被忽略的 `app/tests/`，结果和正常／紧凑窗口截图位于 `app/build-qt/tests/heading-text-test/artifacts/`。已在 Windows 原生预览窗口使用鼠标验证工具组内、协作记录文件夹内及项目列表拖动，并核对保存的顺序；完全退出并重开后再次检查顺序恢复。

工具组修订另行验证了改名后的虚拟组拖到首位，以及实际工具组拖到展开组的子项区域；两次整组移动均保存正确，子项顺序与归属保持不变。
